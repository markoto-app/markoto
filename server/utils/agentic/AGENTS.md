# AI Features — LiteLLM gateway, EU-resident vendor stack

Every AI surface routes through our self-hosted **LiteLLM proxy** at `infra/litellm/`. The OpenAI TypeScript SDK is the client; LiteLLM speaks OpenAI's API shape and multiplexes into:

| Surface | Upstream model | Custom provider? |
|---|---|---|
| Text agentic loop + vision | Mistral Small 4.0 (`mistral-small-2603`) | No — Mistral is OpenAI-compatible end-to-end |
| Voice transcribe (one-shot) | Voxtral Mini Transcribe 2 (`voxtral-mini-2602`) | Yes — `MistralTranscribeProvider` wraps `/v1/audio/transcriptions` as a chat completion so spend tracks correctly |
| Live dictation | Voxtral Realtime via `@mistralai/mistralai/extra/realtime` (direct WS, NOT through LiteLLM) | LiteLLM only sees the per-minute billing tick (`VoxtralTickProvider`) |
| Embeddings | Jina v5-text-nano (768-d native) | Yes — `JinaEmbeddingsProvider` reshapes `usage.total_tokens` → `prompt_tokens` so spend tracks |
| Image generation | BFL FLUX.2 [pro] EU-pinned (`api.eu2.bfl.ai`) | Yes — `BFLFluxProvider` wraps submit+poll as a chat completion |

**The table above lists the BUNDLED deployments.** Since WP4 the chat / image / transcription rows are only used when they are the operator's instance default (`NUXT_AI_DEFAULT_*_MODEL=<alias>`); see "Bring your own key" below.

## Bring your own key (WP4)

Every chat / image / transcription call resolves a provider per user via `server/utils/aiProviders/resolve.ts` — **own config (`user_ai_providers`) → instance default (`NUXT_AI_DEFAULT_*`) → null**. The result rides on the tool context as `MetaToolContext.aiProviders` (resolved once per session at `/api/ai/prompt`, `trigger-ai`, per MCP call, and in `_test/exec-ai-tool`).

- **Request shape**: `providerRequestFields(provider)` (`aiProviders/requestFields.ts`) returns `{ model: 'byok/<id>', api_key, api_base }` for a BYOK provider (re-running the SSRF policy on EVERY call) or `{ model: '<alias>' }` for a platform alias. Spread it into the LiteLLM body (`LitellmCreate*Params` / `LitellmImageParams` accept `api_key` / `api_base`). **Never send `api_key` with a non-`byok/` model** — on a platform deployment LiteLLM would replace the operator's provider key with it.
- **Errors**: wrap BYOK calls in `withProviderErrors(provider, fn)` — re-throws an `AiProviderCallError` whose message has the key redacted (`redactSecret` also strips 8+-char prefixes/suffixes a provider might echo). The chat stream is additionally wrapped in `redactProviderStream(provider, stream)` because errors raised while it is CONSUMED (SSE error events, dropped connections) bypass `withProviderErrors`. Messages from the loop reach the initiator's session channel, the server log and Sentry, so this is load-bearing.
- **Chat loop** (`runLoop.ts#streamFromLiteLLM`): runs on `aiSession.aiProviders.chat`; null → throws (the endpoints already 409 `ai/provider-missing` before opening a session). `filterToolsForProviders` drops `generate_image` without an image provider and `view_image` / `view_pages` for a chat model without vision.
- **web_search / fetch_url (WP6) — who pays what**: the upstream Staan search / Jina Reader call is **platform-paid** (plain `fetch` from the app, never a LiteLLM deployment, so it is invisible to the user's `max_budget`). The synthesis step (`WebToolSpendContext.chatProvider`) runs on the SAME provider as the chat that invoked the tool — the user's own key under BYOK (zero-cost `byok/*`, user pays the provider), the instance default otherwise (debits the budget). No chat provider → raw Staan results / Jina page text unsynthesised. A BYOK model without `json_schema` support makes `fetch_url` fall back to prose (existing `JSON.parse` fallback). Because the upstream half is free to the user, `server/utils/webTools.ts` bounds it: `consumeWebToolQuota(userId)` (called inside `webSearch()` / `fetchUrl()`, so the loop and MCP share ONE allowance) counts a Valkey sliding window per user — `NUXT_WEB_TOOLS_HOURLY_LIMIT` (default 30) and `NUXT_WEB_TOOLS_DAILY_LIMIT` (default 100), `0` = unlimited; fails OPEN on Valkey error, bypassed under `TEST_MODE`. Over the limit it throws a 429 `ai/web-tools-rate-limited` (`data.messageKey` = `ai.webToolsHourlyLimit` / `ai.webToolsDailyLimit`, plus `limitRecovery()`); in the loop `runSubCall` turns that into a tool error the model reads and relays. `fetch_url` only counts after the SSRF guard passed. Availability: `getWebToolAvailability()` (`STAAN_API_KEY` / `JINA_AI_API_KEY` set) — `filterToolsForProviders` drops the tool the operator has no key for, MCP does not list it, and `GET /api/ai/availability` reports `webTools: { search, fetch }`. Don't reintroduce a per-tool-wrapper rate limit; the handler-level allowance is the single control. The monthly free-tier budget reset is LiteLLM-native (`budget_duration: '30d'` on every virtual key, set in `createUserKey` / `updateUserKeyBudget`), independent of Stripe.
- **generate_image**: BYOK → OpenAI images API (`/v1/images/generations` via `litellmImage`, size mapped to 1024², 1536×1024 or 1024×1536; `b64_json` sniffed for PNG/JPEG/WebP, a returned `url` fetched through `fetchExternalImage` = SSRF guard + caps). Alias default → the BFL chat-wrapped convention (only `flux-2-pro`-style chat-wrapped image deployments work as an alias).
- **Transcription** (`/api/ai/transcribe`): BYOK → multipart `/v1/audio/transcriptions` via `litellmTranscription` with `api_key` / `api_base` as form fields (verified on v1.106.4); alias → the Voxtral chat-wrapped custom provider (unchanged, TEST_MODE stub kept for that path only).
- **Live dictation**: `liveDictationTarget()` — the user's own Mistral key (transcription base URL host `api.mistral.ai`; no LiteLLM ticks, Mistral bills the user) or an alias default + operator `MISTRAL_API_KEY` in the app env (ticks bill the user's budget as before). Otherwise the WS closes with 4004 and the mic is hidden client-side.
- **Spend**: the `byok/*` deployment has zero `model_info` cost, so BYOK calls leave `max_budget` untouched while still authenticating with the user's virtual key (rpm limit, spend-log tags). Pinned by `tests/integration/endpoints/aiProviders.test.ts`.

Per-user budget enforcement: every authenticated user gets a LiteLLM virtual key with `max_budget` set to their plan tier. Spend logs carry four-axis tags (`feature:` / `workspace:` / `user:` / `doc:`) for the `/admin/ai-spend` and `/admin/axis-spend` dashboards.

## Four flows

- **Agentic prompt** — one path serving both the bottom `AIPromptBar.vue` and the selection-scoped `AISelectionPopup.vue`. Full tool use: **27 always-on tool declarations + 2 workspace-gated knowledge tools** (`ALL_TOOL_DECLARATIONS` / `KNOWLEDGE_TOOL_DECLARATIONS` in `functionTools.ts`; `filterToolsForProviders` then drops what the session's providers can't serve). The 27: document + theme + render (`view_document`, `replace_text`, `insert_text`, `update_theme`, `get_theme`, `list_themes`, `save_theme_as_preset`, `set_title`, `view_image`, `generate_image`, `get_page_count`, `view_pages`, `export_document_as_markdown`, `search_activity_log`), cross-document (`list_workspace_documents`, `list_my_documents`, `view_other_document`, `create_document`, `duplicate_document`), web (`web_search`, `fetch_url`), comments (`read_comments`, `create_comment`, `reply_to_comment`, `resolve_comment`, `delete_comment`) and `message_to_user`. The loop only dispatches tools it offered to the session — a model naming any other tool gets a tool error. Knowledge gates on (workspace membership AND ≥1 ready file). Model: **Mistral Small 4.0** via LiteLLM (`mistral-small-2603`, $0.15/$0.60/M tokens). The selection popup pre-captures an `EditorSelectionSnapshot` (kind=`selection`) and passes it as `editorSelection` on `/api/ai/prompt`, so the model sees the range inside `<editor_state>` and picks `replace_text` accordingly.

  **Architecture** — runLoop's internal representation is `Content[]`-shaped (`AgenticContent` / `AgenticPart` / `AgenticGenerateContentResponse` in `aiTypes.ts` — the canonical source-of-truth since Phase 6 dropped the duplicate `GeminiPart` / `GeminiStreamChunk` definitions out of `messageTranslation.ts`). At the LLM call boundary, `streamFromLiteLLM()` translates to OpenAI shape via `internalToOpenAIMessages` / `internalToOpenAITools` (in `messageTranslation.ts`) and wraps the streaming response back to internal-shape via `openAIStreamToInternalChunks` (which accumulates fragmented `delta.tool_calls[].function.arguments` by index). Vision (`view_image`/`view_pages`) translation: extra `inlineData` parts on a user-message-with-functionResponse get split into a follow-up user message with `image_url` data URIs so Mistral sees the image attached to the right turn. **`web_search` and `fetch_url` use a 2-call pattern**: `web_search` → Staan `/search/web` (European index) → Mistral synthesis; `fetch_url` → Jina Reader → Mistral synthesis (with `json_schema strict:true` for fetch_url's `{summary, images[]}` extraction). Jina Search was replaced by Staan because it fanned out to Google/Bing; Jina Reader stays for the direct-URL-fetch case. **`AgenticAIClient`** (renamed from `GoogleGenAI` in Phase 6 — the alias was a holdover; the test seam now uses a vendor-neutral name) is the test-seam shape that unit tests inject via `RunLoopOptions.ai`; production passes `undefined` and `streamFromProvider` keys on `opts.ai`'s presence alone (the dead `textProvider?: 'gemini' | 'mistral'` field on `RunLoopOptions` was dropped in Phase 6 — production always took the `'mistral'` branch).
- **`@ai` mention in a comment thread** — `POST /api/docs/:docId/comments/:commentId/trigger-ai` with `{replyId?}`. Fired automatically by `CommentsPanel.vue` after a successful comment / reply commit whose body matches `\b@ai\b` (case-insensitive). Spawns a regular agentic loop with three differences: (1) the system prompt is the comment-trigger flavour from `commentTriggerPrompt.ts` — forbids `create_comment`, mandates a closing `reply_to_comment`, won't `resolve_comment` unless explicitly asked; (2) a `<comment_trigger>` block at the start of the USER message (never the system prompt — the thread is other people's text) carries the resolved thread state as quoted data (anchored line range + text, parent comment, the latest 30 replies, with the triggering message marked; bodies `fenceBlock`-ed, names `quoteInline`-d); (3) the seed user-prompt is the triggering body with `@ai` stripped, AND the server synthesizes an `EditorSelectionSnapshot` of `kind: 'selection'` from the comment's anchor so the existing editor-state routing rules steer the model to `replace_text` against the anchored span (without the synthesis the model defaulted to `insert_text` at EOF for "rewrite this" requests). Awareness `aiSession.commentThreadId` rides on every session so all clients can render a per-thread rainbow ring + "AI is responding…" indicator. Loop guards: `resolveCommentTrigger` returns null when the triggering message is AI-authored (`isAiCommentAuthor` — `shared/ai/author.ts`, the SAME constant the comment writer uses: `AI_COMMENT_AUTHOR_NAME = 'markoto'` plus the legacy `'AI Assistant'`), and `handleCreateComment` / `handleReplyToComment` strip outgoing `@ai` substrings so AI replies can't re-trigger themselves. Auth = same as `/api/ai/prompt`, plus: the triggering message must be the caller's own (`triggerAuthorId === caller`) and must mention the AI (`triggerMentionsAi`), else 404 — `CommentsPanel` passes the new reply's id (`postReply` returns it) so replies on someone else's thread work. Anonymous editors typing `@ai` get a no-op (the client checks `viewerId` before firing).

  **Salvage routing on prose-only turns** (Phase 6): when the model emits text with no tool call, `runLoop.ts` synthesises a closing tool call so the response lands somewhere visible. `RunLoopOptions.commentThreadId` controls the fork:
  - **Comment-trigger sessions** synthesise `reply_to_comment(comment_id=triggerThreadId, body=proseText)`. A successful `reply_to_comment` against the trigger thread is a **hard loop terminator** — even if Mistral pairs it with a hallucinated follow-up `replace_text` in the same turn, the loop ends immediately. Mistral occasionally emits both; without the terminator the rainbow ring stayed lit on the orphaned tool call.
  - **Regular prompt sessions** keep the legacy `message_to_user` synthesis (lands in the prompt-bar response panel).
  Pre-Phase-6, comment-trigger sessions used the same `message_to_user` salvage; prose answers landed in the prompt bar instead of the comment thread, which is wrong UX and the en-light `ai-comment-mention` flow caught it. Pinned by `tests/unit/runLoopProseSalvage.test.ts` (5 cases).
- **Voice input for the prompt bar** (mic button inside `AIPromptBar.vue`) — one-shot transcription. `MediaRecorder` + `AnalyserNode` visualiser in `useVoicePrompt.ts`, POSTs base64 audio + MIME + languageCode to `/api/ai/transcribe` → LiteLLM → Voxtral Mini Transcribe 2 → plain text → auto-submits as a normal prompt. 60s cap, 5 MiB max. No Y.js session — transcription itself doesn't touch the doc; the downstream `/api/ai/prompt` call enforces all the usual content gates. The custom Python provider in `infra/litellm/custom_handlers.py:MistralTranscribeProvider` wraps the audio call as a chat completion so LiteLLM's spend tracker bills correctly.
- **Live dictation into the editor** (mic button in the formatting toolbar) — streaming transcription over a Nitro WebSocket at `/api/ai/dictate`. Interim partials render as ghost text at the CM6 caret; finals commit into Y.js with a `dictation:{userId}` origin. Auth via short-lived JWT sent as the FIRST WS message (NOT `?token=`, which would leak into access logs). One session per user enforced via Valkey `SET NX EX` lock. Upstream is **Voxtral Realtime** via Mistral's official `@mistralai/mistralai/extra/realtime` SDK ($0.006/min). The realtime SDK opens a direct WS to Mistral (NOT through LiteLLM — LiteLLM doesn't proxy stateful WS streams); LiteLLM still sees the per-minute billing tick. Audio format: PCM s16le, 16kHz, mono. See `useVoiceDictation.ts` + `dictationExtensions.ts` + `server/routes/api/ai/dictate.ts`.

  **Voice-tick metering** — the dictate path bills via a 60-second heartbeat. Each tick fires a fake chat completion against the `voxtral-realtime-tick` LiteLLM custom provider (in `infra/litellm/custom_handlers.py:VoxtralTickProvider`) — billing-only stub that reports 60 completion_tokens × $0.0001/token = **exactly $0.006/tick**. Ticks use the per-user virtual key (`useLitellmForUser(virtualKey)`), so spend lands on the right user's `max_budget`. On a `budget_exceeded` error from LiteLLM (HTTP 422 since LiteLLM 1.104, 400 before — `isBudgetExceededError` matches the message, not the status) → close WS with code 1011 reason `budget_exhausted`. On WS close, fire ONE round-up tick if any audio flowed in the partial minute since the last tick (documented overrun: ≤1 extra minute). Transient tick failures silently continue — the next tick retries.

## Document context block

`server/utils/agentic/documentContextPrompt.ts`: every system prompt is prepended with a `<document_context>` block carrying the doc's `title`, `description` (omitted if empty), `language` (resolved to its self-display name via `Intl.DisplayNames` — `de` → "Deutsch"), and the audience-specific tone fragment from `shared/audiences/index.ts`. Title, description and language are set by any editor, so they go in as quoted data (`quoteInline`: JSON-quoted, newlines flattened, `<`/`>` neutralised, capped) — see "Untrusted text in prompts" below. The schema enforces NOT NULL with sensible defaults (`description=''`, `audience='casual'`, `language='en'`), so this block is **always** present — the AI gets durable doc context every turn without the user re-typing. Free-text languages ("Schwiizerdütsch", "Romansh") pass through (quoted) into the "Write all prose in X" instruction.

## Thinking budget

`NUXT_GOOGLE_THINKING_BUDGET` (default `0` = disabled, cheapest/fastest). Env-name retained for compat. Applied only to the main agentic loop. We only pass `thinkingConfig` when `budget > 0`.

## AI-as-Y.js-client + the initiator-only channel

Server mints a JWT (`userId=ai:assistant:{sessionId}`), opens a `HocuspocusProvider`, sets awareness `{user: {isAI}, aiSession: {sessionId, initiatorName, initiatorUserId, commentThreadId?}, aiStatus: {phase, message: null}}`. Each edit is `ydoc.transact(fn, 'ai:assistant:{sessionId}')` — users watch edits land in real time. The `AiSession` interface exposes `docId` and `initiatorUserId` so tools can attribute audited writes (e.g. `uploads.uploaderId` from `generate_image`) to the real human initiator rather than the synthetic AI principal.

**Awareness reaches every participant** (read-only viewers and anonymous visitors of open docs included), so it carries ONLY what everyone may see: who the AI works for and the coarse phase ("markoto is working…"). Everything else is private to the initiator and goes through **`sessionChannel.ts`** (`AiSessionChannel`, Valkey keys `ai:session-channel:{sid}:*`, 15-min TTL so the client can read the final state after the AI left): the prompt, status messages (`updateStatus(phase, message)` → phase to awareness only when it changes, message to the channel), `message_to_user` answers (`DocToolContext.deliverResponse`), and confirmation requests + answers. One key per field, one writer each — no read-modify-write races. The client follows it through the **push stream** `GET /api/ai/sessions/:sessionId/stream` (Server-Sent Events, `sessionStream.ts`) and answers via `POST /api/ai/sessions/:sessionId/confirm`; `GET /api/ai/sessions/:sessionId` is the polling fallback and the one final read after the session left the doc. All three are initiator only (404 for anyone else — same as an unknown id). Every channel write also PUBLISHes a data-less ping on `ai:session-channel:{sid}:notify` (Valkey pub/sub, every instance; one shared subscriber connection per process, `useValkeySubscriber()`); the stream re-reads the keys on a ping and sends a `status` event (same JSON as the GET, `toSessionView`) only when the view changed, re-reads every 5 s anyway (lost ping / subscriber reconnect; the `: ping` comment also keeps Bun's 10 s idle timeout away), sends `end` 3 s after a terminal phase (the client then closes instead of reconnecting) and simply closes after 10 min (EventSource reconnects). Disconnect = the response body's `cancel` (the bun preset's mock Node request never emits `close`). The client (`useAI.ts`) falls back to 600 ms polling when the browser gives up on the stream (HTTP error) or after 3 consecutive errors without a message. Measured in `tests/nuxt/useAI.test.ts`: a 3 s session with an update every 300 ms costs 6 polling requests vs. 1 stream + 1 final read (≈ 100 requests/minute saved per running session). Status/response writes are best-effort; a confirmation that can't be stored or read is DENIED (fail closed). MCP's `mcpStatus` awareness slot is phase-only too.

## Taint + confirm gate (`crossBoundary.ts`, `sessionGuard.ts`)

The loop runs with the invoker's identity; text written by OTHER people can carry instructions (prompt injection) aimed at the invoker's other documents, knowledge or the web. Each session tracks whether it has received content the invoker didn't write:

- **Starts tainted** when the session document isn't solo (`isDocSoloForUser`: owner = invoker, not `open-edit`, no other admin/editor in its workspace, and every content-changing activity row — `edit`, `title.changed`, `theme.changed`, `restore` — attributable to the invoker directly or via their `ai:assistant:` / `mcp:` / `restore:` / `seed:` principals; `server/repos/docProvenance.ts`), or for an `@ai` thread with other participants.
- **Provenance of AI edits** (`ai_session_provenance`, `sessionProvenance.ts`): both endpoints write a row `(session_id, doc_id, user_id, clean = false)` right after claiming the session (before the AI client can write; failure releases the session and fails the request) and flip `clean = true` in their `finally` — after `aiSession.destroy()` — only when the session's guard never tainted. An `ai:assistant:<sid>` edit counts as the invoker's own only with a provenance row of theirs that is clean; another user's session, a tainted / still-running / crashed session, a failed update → foreign (fail closed). So the invoker's own `@ai` comment sessions (which write no conversation memory, and whose `ai_sessions` row is gone after the session) no longer make their private doc "shared", while a session that had read someone else's content can't launder that content into "the invoker's own" text. Sessions from before the table (no row) keep the old rule (live `ai_sessions` row or conversation memory of the invoker). The query wraps its "is this row the invoker's" test in `COALESCE(…, false)`: before F-7b the bare `NOT (user_id = X OR …)` evaluated to NULL for every row without a `user_id` (all AI, MCP and anonymous edits), so such rows were silently never foreign. Rows live as long as the doc / user (FK cascade), are exported as `ai/edit-provenance.ndjson`. Pinned by `tests/repos/docProvenance.test.ts` + the F-7b cases in `tests/integration/endpoints/aiCrossBoundary.test.ts`.
- **Becomes tainted** after `web_search`, `fetch_url`, external `view_image`, `list_workspace_documents` (when someone else can edit in the workspace), `view_other_document` of a non-solo doc, `read_comments` with other authors (AI-named comments count as own only on a solo doc — the name is client-writable), `search_knowledge` when any ready file was uploaded by someone else, `get_knowledge_file` of such a file (or an unknown id).
- **Once tainted**, `list_my_documents`, `list_workspace_documents`, `view_other_document`, `search_knowledge`, `get_knowledge_file`, `create_document`, `duplicate_document` and `web_search` pause the loop and ask the invoker in the prompt bar (`AIConfirmPanel.vue`: "markoto wants to read 'Q3 plan' — Allow / Deny", the label resolved with the invoker's own access). `fetch_url` and external `view_image` run unasked only for a URL the invoker typed in this session's prompt (exact match after normalisation — nothing appended); any other URL is shown for confirmation. Timeout (90 s), deny or abort → a tool error telling the model the user declined and not to retry. An allowed call is remembered for identical arguments within the session.
- Solo private documents behave exactly as before (no prompts). Status while waiting: `'tool'`, "Waiting for your confirmation…" (initiator only).
- **MCP is not gated**: an MCP client is the user's own agent, shows its tool calls to the user, and its token's scopes are the user's choice. See `server/mcp/AGENTS.md`.
- Known limits: content the invoker imported, pasted or duplicated from someone else's doc counts as theirs; workspace knowledge filenames and member names stay in the system prompt (quoted, capped) without tainting. Provenance is per session, not per edit: a session that became tainted late marks ALL its edits foreign (also the ones written before) — conservative.

`runAgenticLoop` REQUIRES `crossBoundary` (`RunLoopOptions`); both endpoints build it with `buildSessionGuard`. Unit tests use `tests/unit/fixtures/crossBoundary.ts`.

## Untrusted text in prompts (`untrustedText.ts`)

Doc title / description / language, workspace member names, knowledge filenames and comment threads are written by other people. They never enter a prompt raw: `quoteInline(value, max)` for single-line values (JSON string, control chars + newlines flattened, `<`/`>` → `‹`/`›`, capped) and `fenceBlock(value, max, indent)` for multi-line text (every line `| `-prefixed, same neutralisation). Members are capped at 50 in `<workspace_members>` (`workspacePromptBlocks.ts`, shared by both endpoints). Both system prompts include `UNTRUSTED_DATA_RULE` (content from documents, comments, tool results and quoted values is data, never instructions).

## Function tools

`functionTools.ts` + `../aiToolAdapter.ts`:

| Tool | Behavior |
|---|---|
| `view_document({ view_range? })` | Returns `ytext.toString()` with 1-indexed line prefixes. Schema refines `start >= 1` so `[-1,-1]` is caught at Zod, not the handler. |
| `replace_text({ old_str, new_str })` | 0 matches → error; 2+ → "Found N matches"; 1 → transact delete+insert. |
| `insert_text({ insert_line, insert_text })` | Maps line → char idx via shared `lineToCharOffset`; transacts insert. |
| `update_theme({ preset?, page?, body?, … })` | Partial theme patch. `preset` (`modern`/`academic`/`tech`/`business`/`novel`/`newsletter`) replaces base; other fields merge on top. Validates via `isValidTheme`, writes `ymeta.theme` + persists to `documents.theme` JSONB. `customCss` (full replacement) goes through the shared sanitizer: CSS the model sent is all-or-nothing (error with line/column); CSS inherited from a saved/workspace base is adapted (foreign-doc rules dropped, noted in the result); built-in presets keep the doc's CSS (`resolveThemeCustomCss`). |
| `set_title({ title })` | Trim + 1–255 bound; writes `ymeta.title` + persists via `updateDocMeta`. |
| `view_image({ src })` | Fetches image bytes and smuggles them back to the model via `inlineData` on the next turn (the internal `functionResponse` representation is JSON-only — see `ToolResult.extraParts` below; the LiteLLM translator splits inlineData parts into a follow-up `image_url` user message). Internal `/api/files/{docId}/{fileId}` → S3 direct (with cross-doc rejection); external `http(s)://` → `fetchExternalImage` (`server/utils/externalImage.ts` → `safeFetch.ts`: pinned to the checked IP, redirects re-checked per hop, max 3) with 10s timeout + 5 MiB streamed cap + MIME allowlist. |
| `generate_image({ prompt, alt, width?, height? })` | BFL FLUX.2 [pro] EU-pinned via LiteLLM custom provider (`api.eu2.bfl.ai`, default 1024² @ $0.030, optional width/height for non-square — meters by megapixel). Uploads to S3 and returns the markdown reference; AI follows up with `insert_text`/`replace_text`. Server-side PUTs deliberately omit `ServerSideEncryption` — SeaweedFS rejects unknown SSE headers; the browser presigned-PUT path already trusts bucket-default encryption. The BFL custom provider lives in `infra/litellm/custom_handlers.py:BFLFluxProvider` and disables `prompt_upsampling` because the prompt is AI-written. |
| `web_search({ query })` | 2-call pattern: Staan `/search/web` (European search index, `api.staan.ai/v2`) returns ranked title/url/snippet results → Mistral synthesis produces a freeform answer + deduped source list. `STAAN_API_KEY` read in-process; EU-only routing is an account setting. **Rate-limited per user (`consumeWebToolQuota`) and only offered when `STAAN_API_KEY` is set. The synthesis authenticates with the caller's LiteLLM virtual key** (`WebToolSpendContext.virtualKey`, threaded from `billingContext.virtualKey` in-loop / `MetaToolContext.virtualKey` in MCP) so its token spend counts against the user's `max_budget` — NOT the master key. Admin-key fallback only for a key-less harness path. |
| `fetch_url({ url })` | 2-call pattern: Jina Reader extracts the page → Mistral synthesis at `temperature: 0` with `json_schema strict:true` produces `{summary, images[]}`. Scheme-less URLs get `https://` prepended. Synthesis bills the caller's virtual key (same `WebToolSpendContext.virtualKey` path as `web_search`). |
| `search_knowledge({ query, top_k? })` | Hybrid search over `workspace_knowledge_chunks` (vector cosine via HNSW + BM25 via `ts_rank_cd`) fused via Reciprocal Rank Fusion (`k=60`). Returns top-K with `semantic=…` + `lexical=…` score breakdown. Only exposed when the session has a workspaceId AND the workspace has at least one `status='ready'` file. |
| `get_knowledge_file({ knowledge_id })` | Returns the cached markdown of one knowledge file, truncated to 40k chars. knowledge_ids come from the `<knowledge_files>` system-prompt block — fabrication is rejected. |
| `read_comments({})` | Walks `Y.Array<Y.Map>` named `comments`, resolves each anchor (`Y.RelativePosition` base64 → from/to chars → line numbers), formats id + anchor preview + author + body + reply chain. Returns `[orphaned]` when an anchor's underlying text was deleted. Strips `@[Name](user:N)` to bare `@Name` for display. |
| `create_comment({ start_line, end_line, body })` | Anchors a new comment via `lineToCharOffset` → `Y.createRelativePositionFromTypeIndex` → `Buffer.from().toString('base64')` (NOT `btoa` — server context). Author is `{authorId: null, authorName: AI_COMMENT_AUTHOR_NAME}` (`'markoto'`, `shared/ai/author.ts`). Strips `@ai` from the body before insert (loop guard). |
| `reply_to_comment({ comment_id, body })` | Pushes a reply Y.Map into the parent's `replies` Y.Array, bumps parent `updatedAt`. Same AI author + same `@ai` strip as `create_comment`. |
| `resolve_comment({ comment_id, resolved })` | Sets `resolved` on the parent map. No authorization gate — matches client-side semantics where any editor can resolve. |
| `delete_comment({ comment_id, reply_id? })` | Pass `reply_id` to delete one reply; omit it to delete the whole thread. Permitted when authored by AI, by the session initiator, or when `canManageDoc(initiatorUserId, docId)` returns true. |

**Tool declarations are split:** `ALL_TOOL_DECLARATIONS` = the 27 always-on declarations; `KNOWLEDGE_TOOL_DECLARATIONS` = the 2 workspace-gated tools. `server/api/ai/prompt.post.ts` concatenates them only when the session has workspace access AND at least one ready knowledge file, AND appends a `<knowledge_files>` block listing `{knowledge_id, filename (quoted), sizeBytes, sourceExt, tokenCount}`. **Comment-trigger sessions** use the SAME tool list but a different system prompt (`COMMENT_TRIGGER_SYSTEM_PROMPT`) that bans `create_comment` and mandates a closing `reply_to_comment`.

**`ToolResult.extraParts`:** tools whose output includes binary data (currently `view_image` with inline image bytes) return a `ToolResult` with an `extraParts: Part[]` field; the runLoop appends those sibling parts on the user message AFTER the `functionResponse`. Our internal `functionResponse.response` shape is JSON-only — this is the smuggling path for anything non-JSON. The OpenAI translation layer reshapes the trailing `inlineData` parts into a follow-up `image_url` user message so Mistral sees the image attached to the right turn.

**Source-of-truth for schemas:** Zod drives everything. `z.toJSONSchema(schema, { target: 'draft-7' })` generates both the OpenAI/Mistral param schema AND the runtime validator. Drift-prone strings in the system prompt (preset names, font-category hints) are derived at module load from `THEME_PRESETS` / `THEME_FONTS`, so adding a preset/font automatically propagates.

**The `decl()` field MUST be `parameters`, NOT `parametersJsonSchema`.** This is the single most load-bearing field name in the AI loop. `decl()` in `functionTools.ts` writes the JSONSchema into `parameters`; `internalToOpenAITools` in `messageTranslation.ts` reads `parameters`; both `AgenticFunctionDeclaration` and the OpenAI SDK's `ChatCompletionTool['function'].parameters` type the field as `parameters`. **Do not rename it.** Phase 6 history: a Phase 5 refactor wrote it as `parametersJsonSchema` while readers stayed on `parameters`. TypeScript didn't catch the mismatch (excess-property checks on `return {literal}` from typed functions are unreliable in TS), so every tool went out to Mistral with an empty params schema — no fields, no required, no hints. Mistral improvised arguments, often emitted empty `{}`, and Zod rejected. We thrashed on retry / salvage paths. This single bug explained the entire en-dark AI flake cluster (`ai-cross-doc`, `ai-fetch-url`, `ai-generate-image`, `ai-rewrite-selection`, `ai-web-search`) AND the en-light `ai-comment-mention` failure. Pinned by `tests/unit/aiToolSchemas.test.ts` — assert against the literal field `parameters`, not via type coercion.

## Temperature

The main agentic loop pins `temperature: 0` in `streamFromLiteLLM` (matches the existing `temperature: 0` on `web_search` / `fetch_url` synthesis sub-calls). Default Mistral sampling (~0.7) caused tool-selection drift run-to-run on a deterministic-ish task ("read the doc, pick the right tool, edit, wrap up"). Pinning to 0 stabilises tool choice; flow tests stop flaking on "model decided to chat instead of editing".

**Authorization:** All AI routes check `requireDocEditAccess(docId, userId)` before starting. Workspace viewers and non-members are blocked there, so every tool inherits "content-edit" permission.

**Limits:** there is no app-side prompt rate limit — the per-user LiteLLM virtual key's `rpm_limit` (60) and `max_budget` are the gate (BYOK calls are zero-cost, so only rpm applies). Prompt deadline 5 min, `MAX_TURNS = 20`. Sweeper aborts sessions >7 min (threshold intentionally above prompt deadline). Final status lingers (2.5 s after an error, 0.5 s otherwise) before the AI leaves the doc; the channel keys outlive it so the client still reads the final answer / error.

**Per-session safety caps** (`server/utils/agentic/limits.ts`):
- `SESSION_INTERACTION_CAP = 50` — total interactions any one session can accumulate across turns + sub-calls. A normal session uses 3-8; >50 means tool-call ping-pong, prompt-injection amplification, or a runaway loop. **On hit the loop ABORTS** via the existing `setStatus('error', …)` path — the model doesn't get a chance to recover. These are runaway-loop SAFETY caps; the per-user monthly interaction budget (Stripe-aligned) is the BUSINESS cap. Both layers are needed: a single runaway prompt should never drain a paid user's monthly budget on one session.
- `SESSION_TOOL_CALL_CAPS` — per-tool ceilings within one session: `view_pages: 3`, `generate_image: 5`, `web_search: 10`, `fetch_url: 10`, `search_knowledge: 20`. **On hit returns a TOOL ERROR** (not an abort) — the model sees the cap and can finish its reply gracefully without further tool use. Numbers picked from "what does a pathological loop look like": e.g. 5 image gens × $0.030 (BFL FLUX.2 [pro] @ 1024²) ≈ $0.15 worst-case session; 10 web searches × Jina pricing ≈ a few cents. Above those is research-style usage that should be split across sessions.

**SSRF guard** (`server/utils/agentic/urlGuard.ts`): every URL-taking tool — `view_image` (external `http(s)://` branch), `fetch_url` — calls `assertSafeUrl(url)` before forwarding. Catches private CIDRs (RFC 1918, CGNAT, link-local incl. AWS/GCP metadata `169.254.169.254`, multicast, broadcast), loopback, in-cluster service banners (Postgres / Valkey / Hocuspocus / Nuxt's own internal endpoints), and non-`http(s)` schemes (`file://`, `gopher://`, `dict://`, `ftp://`). DNS-resolved hostnames are looked up once and every resolved IP is checked; addresses are classified from their bytes (`classifyIp`), so IPv4-mapped (incl. hex `::ffff:7f00:1`), IPv4-compatible, NAT64 and 6to4 forms are judged by the embedded IPv4 and Teredo / documentation / reserved space is refused. Where the APP connects (`view_image`), `safeFetch.ts` dials the checked IP and re-checks every redirect hop, so rebinding and redirects can't reach internal targets; `fetch_url` forwards the parsed `URL#href` (≤ 2000 chars) to Jina Reader, which fetches from its own network. Don't add a new URL-taking tool without routing it through this guard — and through `safeFetch` if the app itself fetches.

**Session telemetry**: every agentic-loop run emits exactly one Sentry event at session-end via `Sentry.captureMessage('ai-session-completed', …)` from the `finally` block in `runLoop.ts`. Tags: `component: 'ai-session'`, `event: 'completed'`, `outcome ∈ {ok, abort, error}`, `docId`, `initiatorUserId`. Extras: `sessionId`, `turnCount`, `totalInteractions`, `totalInputTokens` / `totalOutputTokens` / `totalThinkingTokens` (each `-1` when the SDK never surfaced `usageMetadata` — preserves "no data" vs "actually 0"), `toolCallCounts: Record<string, number>`, `abortReason`, `errorMessage`, `durationMs`. Wrapped in a try/catch so a Sentry transport hiccup never propagates into the agentic loop's caller — failed telemetry must be invisible to the user.

**Cancellation:** `POST /api/ai/abort` — 404 if ended, 403 if not initiator. Status → `{phase:'done', message:'Stopped'}`.

**Per-user cap:** 1 session per user per doc, enforced by Postgres UNIQUE index in `ai_sessions`.

**Frontend status display:** `describeToolInput` in `streamStatus.ts` has a labelled case for every tool. The message reaches the initiator only (session channel): `AIPromptBar.vue` shows it as the input placeholder. Everyone else sees "markoto is helping <name> — markoto is working…" (`PresenceBar.vue` tooltip, `ai.workingGeneric`) and, in the prompt bar's other-sessions badge, only the initiator's name.

## Live dictation stack

**Transport:** Nitro native WebSockets (`nitro.experimental.websocket: true`). Single WS route: `server/routes/api/ai/dictate.ts` implements `{ websocket: { upgrade, open, message, close, error } }` hooks. An HTTP fallback on the same path 426s.

**Protocol** (head-comment in handler):
- Server → client: `{type:'hello'}` on open → `{type:'ready'}` after auth + STT up → `{type:'partial', text}` / `{type:'final', text}` → terminal frames `budget-exhausted` / `session-cap` / `idle-timeout` / `error`.
- Client → server: `{type:'auth', token, languageCode?}` as the FIRST message → binary PCM chunks → `{type:'stop'}`.

**Text-vs-binary detection:** crossws + the Node `ws` library deliver TEXT frames as Buffer, so `typeof rawData === 'string'` never matches. `tryParseControl` in `dictateHelpers.ts` peeks the first byte for `{` (0x7B) before attempting `JSON.parse` + whitelisting `type` — audio chunks that coincidentally start with `{` don't get routed as control frames.

**Auth lifecycle:** `POST /api/ai/dictate/token` mints a 60s JWT signed with `config.google.dictateJwtSecret` (falls back to `config.jwtSecret` for dev). Middleware whitelists `/api/ai/dictate` because the WS upgrade hook gets a raw Request (not an H3Event). The `open` hook arms a 5s auth-deadline timer.

**Concurrent-session cap:** `tryAcquireSessionLock('ai-dictate-active', userId, SESSION_HARD_CAP_MS)` — Valkey `SET NX PX` cluster-wide. Fails CLOSED on Valkey errors (correctness lock; failing open would double-bill GCP). Released on every WS close/error hook.

**Audio-seconds budget:** `consumeRateLimitBudget('ai-dictate-ms', userId, CHUNK_AUDIO_MS, DAILY_BUDGET_MS, DAILY_WINDOW_MS)` — 30 min/user/day in ms, not requests. Each AudioWorklet chunk (2048 samples @ 16 kHz = 128 ms) debits 128. Peek mode (`cost: 0`) returns the REAL remaining (`maxCost - current`) — naive `maxCost` would let exhausted users open then trip on first chunk.

**Client state machine** (`useVoiceDictation.ts`): `idle → requesting-permission → connecting → recording → idle/error`. VueUse: `useUserMedia` for stream lifecycle (explicit `track.stop()` on unmount), `useWebSocket` with both `immediate: false` AND `autoConnect: false` (default `autoConnect:true` watches the URL ref and races the explicit `.open()` call → spawns TWO sockets per click).

**CM6 integration** (`app/utils/dictationExtensions.ts`): `StateField<string>` holds interim text, `ViewPlugin` rebuilds a `Decoration.widget` at the caret on every state-field/doc/selection change. `commitDictationFinal` inserts via `ydoc.transact(fn, 'dictation:{userId}')` with smart spacing (mid-word `fo|o` + "bar" → `fo bar o`).

**Straggler-chunk guard:** `stt.end()` on `{type:'stop'}` sets `ctx.sttEnded = true`. Audio chunks already queued by the browser's worklet → postMessage queue → WS pipeline (~128 ms window) land post-end; the flag drops them before they hit `stt.write()`. Second defense: SpeechClient's error listener silently swallows "write after end" when the flag is set.

**Mock for tests:** `createDictateSpeechClient(apiKey)` returns a real Mistral Realtime client or, when `TEST_MODE=1` + `NUXT_GOOGLE_SPEECH_MOCK=1` (env-name retained for compat with existing CI configs even though the upstream is now Mistral), a fake that emits canned interim → final responses on fixed chunk thresholds.

## Gotchas

- **`decl()` field MUST be `parameters`, not `parametersJsonSchema`.** See the source-of-truth section above for the bug history. Pinned by `tests/unit/aiToolSchemas.test.ts`.
- **Zod `z.tuple(...)` is rejected by some models' schema validators** — use `.array().min(N).max(N)` for vector-shaped inputs (e.g. `view_range`).
- **AI sweeper threshold must exceed prompt deadline** (7 min > 5 min) — otherwise legit long web searches get killed.
- **Mistral sometimes hallucinates tool outputs** — placeholder URLs like `/api/files/placeholder/joel.png`. System prompt explicitly forbids fabricating `/api/files/...` paths.
- **`z.string().trim().min(1)` ordering matters in Zod 4** — put `.trim()` BEFORE `.min(1)` so the length check sees the trimmed value.
- **`view_range: [-1, -1]` keeps coming back** — enforce `start >= 1` with a `.refine` so the model gets a schema-level rejection it self-corrects from.
- **LiteLLM `metadata.tags: string[]` cast pattern.** Every `litellm.chat.completions.create({...})` call site has to cast as `as unknown as Parameters<typeof litellm.chat.completions.create>[0]` (double-cast through `unknown`), NOT the simpler single cast. Reason: our request shape adds `metadata: { tags: string[] }` for the four-axis spend tagging, but LiteLLM's published `Metadata` type is `Record<string, string>` — `tags: string[]` doesn't structurally overlap, so a single `as Parameters<...>[0]` errors. The double-cast is the proper escape hatch and survives SDK upgrades that don't touch our spend-tag shape. There are 8 such sites across the agentic helpers (main loop, web_search synthesis, fetch_url synthesis, image-gen, transcribe, dictate-tick, plus two test seams).
- **LiteLLM streaming-vs-completion result-cast.** `litellm.chat.completions.create()` returns `Stream<Chunk> | ChatCompletion` typed as a union — `.choices` and `[Symbol.asyncIterator]` both error on the union. Cast non-streaming results to `OpenAI.Chat.Completions.ChatCompletion` and streaming results to `AsyncIterable<OpenAI.Chat.Completions.ChatCompletionChunk>` AT THE CALL SITE. Don't try to discriminate via `if ('choices' in resp)` — both branches structurally satisfy it on different paths.
- **`AgenticGenerateContentResponse.candidates[].content` MUST keep `role?: string`.** Phase 6 dropped the local Gemini types but the test seam's chunk shape still passes `role` on streamed deltas; without the optional field the test mocks fail to typecheck. The runtime never reads `role` on candidate content — the field is structural-only.
- **`finishReason` enum narrowing.** `runLoop.ts` narrows `string | AgenticFinishReason` via `Object.values(FinishReason).includes(reason)` and falls through to `OTHER` for unmapped strings (Mistral occasionally returns `'tool_calls'` / `'eos'` etc.). Don't relax to `as AgenticFinishReason` — the explicit check survives upstream string drift without throwing.
- **`dictateSpeechClient` Mistral SDK union narrowing.** `@mistralai/mistralai/extra/realtime` events arrive as `TranscriptionStreamTextDelta | UnknownRealtimeEvent`. Type-guard via `'text' in event` before reading `event.text` — the unknown variant is a forward-compat catch-all and is intentionally typeless.
- **`@mdit/plugin-alert` doesn't support `> [!NOTE] Custom title`** — text after `[!KIND]` on the first line is silently dropped.
- **`data-*` attributes don't survive DOMPurify** — only `class`, `id`, `style`, `width`, `height`, `aria-*`, `role`, `target`, `rel`, `title` survive on most elements.
- **AI `extraParts` must come AFTER the `functionResponse`** — the model links binary parts to the most-recent function call on the same user message.
- **User-facing strings say "AI session", not "Gemini session".** `server/utils/aiSessions.ts` + `server/api/ai/abort.post.ts` were normalised in Phase 6; the display name is vendor-neutral throughout.
- **`MediaRecorder` MIME preference** — Chrome/Firefox want `audio/webm;codecs=opus`, Safari falls back to `audio/mp4`. Server's `ALLOWED_MIME` list must stay in lockstep or Safari recordings 400.
- **Always `track.stop()` on every `MediaStream` track explicitly** — just stopping `MediaRecorder` leaves the audio tracks live and the browser's "site is using your microphone" indicator stays on.
- **`String.fromCharCode(...bytes)` blows the stack on large buffers** — chunk in 0x8000-byte slices when converting audio `ArrayBuffer` → base64.
- **`useWebSocket` has TWO independent flags** — `immediate` AND `autoConnect`, both default true. Set both to false for manual lifecycle control.
- **`tryAcquireSessionLock` fails CLOSED, `consumeRateLimitBudget` fails OPEN** — opposite polarity by design. Don't accidentally flip either.
- **`consumeRateLimitBudget` with `cost: 0` must PEEK the actual remaining** — earlier version returned `maxCost` unconditionally which let exhausted users open then trip on first chunk.
- **JWT in first WS message, NOT `?token=`** — query-string auth leaks into access logs, referer headers, and browser history.
- **Knowledge tools are in a SEPARATE declaration array** — `KNOWLEDGE_TOOL_DECLARATIONS` is concatenated to `ALL_TOOL_DECLARATIONS` only when the session has workspace access AND ≥1 ready file.
- **AI must end every turn with a tool call** — there's no chat surface for model prose (`message_to_user` is the conversational channel, delivered to the initiator only). Prose-only turns are salvaged (see above).
- **Never put session details into awareness.** Anything other than `{sessionId, initiatorName, initiatorUserId, commentThreadId}` + the phase is visible to every participant. Prompt, status text, answers, confirmations → `AiSessionChannel`.
- **A new tool that reads other people's content or reaches beyond the current doc** must be added to `crossBoundary.ts` (`CONFIRM_WHEN_TAINTED` and/or the taint switch in `afterTool`) — otherwise it bypasses the gate.
- **`@ai` is regex-detected at the client, NOT typed-into a structured token.** Detection regex `/(^|[^\w@])@ai(?=[^\w]|$)/gi` — the leading non-`\w`/`@` lookbehind avoids matching emails (`joel@ai.example.com`); the trailing lookahead avoids word extensions (`@aim`, `@aiding`). Server uses the SAME regex (`stripAiMention` / `hasAiMention` in `commentTriggerPrompt.ts`).
- **Anchor base64 on the server uses `Buffer`, NOT `btoa`.** `btoa` is browser-only. Symptom of getting this wrong: `ReferenceError: btoa is not defined` only in the comment-trigger path.
- **The `@ai` trigger endpoint reads the live Y.Doc via `openTrustedCommentClient`, not the AI session's Y.Doc** — peek-only, ~10 ms, doesn't force the full AI session sync.
- **`onSubmitReply` doesn't thread `replyId` through the trigger endpoint yet** — the reply id from `postReply` is not passed up; falls back to the parent body and renders the full reply chain in `<comment_trigger>`. Fix when refactoring `useComments.ts`.
- **`@ai` typeahead row is synthetic; doesn't come from `mentionable-users`** — `CommentsPanel` prepends a `{kind: 'ai', ...}` entry so it surfaces on standalone docs too. The AI entry has no DB row and no avatar.
