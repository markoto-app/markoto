# API Routes

`server/api/` → `/api/*`. `server/routes/` → `/`. `server/auth/` is unreachable.

**Auth:** `GET /auth/github`, `GET /auth/google`, `GET /api/_auth/session`

**Meta:** `GET /api/health` (cached aggregator probing Postgres + Valkey + sync + **S3** + renderer + markitdown + LiteLLM; 200/503 for Traefik; minimal body — per-component only on 503; 5s healthy / 2s degraded TTL), `GET /api/status` (public per-component board for an external status page — **always 200**, per-component `{status, latencyMs}`, NO error strings; shares the `/api/health` TTL cache), `GET /api/health/deep` (auth-required, no cache, returns per-component `{status, latencyMs, error?}`), `GET /api/version` (SPA staleness). **S3 is probed (HeadBucket) but NON-gating** in `isOverallHealthy` — an object-storage blip shows as degraded on the status board but never 503s a single-instance node out of rotation (uploads/backups break, core doc editing doesn't). See `server/utils/healthProbes.ts`.

**Documents:** `POST /api/docs` (anon OK; accepts optional `workspaceId` + new-doc-dialog fields `title`/`description`/`audience`/`language`/`templateId`/`themePreset`, all validated against the registries; a template is text + design, so `templateId` without `themePreset`/`themeId` also applies the template's design + cover placeholders, retired ids like `academic-paper` are stored as the current one — `shared/templates/AGENTS.md` — empty body = legacy zero-config flow; optional `content` (Markdown ≤ `INITIAL_CONTENT_MAX_LENGTH`, `shared/config/docCreate.ts`, checked before the anonymous gate; 400 `docs/content-too-long`; not with `templateId`) is written as the doc's first `yjs_documents` row — used by the marketing `::try-it` block), `GET/PUT /api/docs/:id/meta` (GET: same access decision as `/token`, denied callers get only `{accessMode, hasPassword, requiresPassword, forbidden}`, a password-unlock JWT as Bearer unlocks the full shape; PUT validates description ≤500, audience enum, language ≤50; owner-only), `DELETE /api/docs/:id` (owner / workspace admin; anonymous docs only by the creating browser's `markoto-anon-creator` cookie), `GET /api/docs/:id/token` (consolidated: token + readOnly + requiresPassword + forbidden + accessMode + ownerId + workspaceId + workspaceRole + theme + description/audience/language for editor hydration + `initialBody` (server-rendered template body, locale-matched on doc.language) + templateId), `GET /api/docs/:id/activity`, `GET /api/docs/:docId/activity/:activityId/diff` (Tier 1 — replays Y.js up to before/after boundaries, returns `structuredPatch` hunks; whitelisted public, auth via `decideActivityAccess`), `GET /api/docs/:docId/activity/:activityId/comment-context` (Tier 1 comment expansion; same auth shape), `POST /api/docs/:docId/activity/:activityId/restore` (Tier 2 — edit-access required; calls `restoreDocToYjsId` then writes `restore` activity row; atomic on failure), `POST /api/docs/:id/password` (set: min 8 chars; verify: only while password-protected, brute-force limited, viewer stays read-only), `PATCH /api/docs/:id/workspace` (move; `canManageDoc` on source + admin/editor on target), `POST /api/docs/:id/duplicate` (first asks the sync-server to persist the source's pending edits — `/internal/flush-document` — then clones row + Y.js state with URL rewrite + S3 assets; `canEditDoc` on source, new owner = duplicator; description/audience/language/templateId copy through unchanged; honours `Idempotency-Key` via `withIdempotency` so a network retry mid-clone doesn't produce two; the copied images are attributed to the duplicator and must fit their image quota — else 409 `upload/storage-quota`), `GET /api/docs/:id/file-token` (public route, same `decideFileAccess` gate as `/api/files` — session or the doc JWT as Bearer; returns `{token, expiresAt}`, a 15-min `file-access` JWT the editor appends to its own image URLs for the sandboxed preview/print iframes; 60/IP/min; `Cache-Control: private, no-store`), `GET /api/docs/:id/pdf` (server-rendered PDF via `renderClient.renderDocument` → renderer sidecar → S3 manifest cache; rate-limited 10/client/min — an allowance shared with the MCP render tools, `utils/renderRateLimit.ts` — view-access required; the 302 and the PDF bytes are `Cache-Control: private, no-store`; `?response=json` answers `{url}` with the same presigned URL instead of the 302, for scripts that must show a refusal as a message).

**Internal (sync→app, `X-Internal-Secret`):** `POST /api/internal/activity` (sync→app activity logging; the sync-server stamps `yjsDocIdBefore`/`yjsDocIdAfter` boundary ids per row so Tier 1 diffs + Tier 2 restores can replay; returns `{ success: true, logged: false, deduped: true }` when the cross-instance partial-unique-index race fires and the second insert is a no-op), `POST /api/internal/comments-snapshot` (per-thread state snapshot triggered on every comment.* mutation; serialised by `pg_advisory_xact_lock(hashtext(docId))` so concurrent writes don't both read the same `latest_id` and produce identical phantom snapshots), `GET /api/_internal/render-bootstrap` (renderer-token-gated; serves the doc's replayed Y.js body + theme/properties — ymeta first, row fallback, `utils/docProperties.ts` — to the renderer's headless print page).

**Sessions:** `POST /api/user/sessions/revoke` ("log out everywhere": bumps `users.session_epoch`, clears the caller's cookie, audited `account.sessions_revoked`). Account delete, `POST /api/user/export` and BYOK `PUT|DELETE /api/user/ai-providers/:capability` need a sign-in ≤ 12 h old → else 401 `auth/reauth-required`.

**User:** `GET /api/user/documents`, `GET /api/user/workspaces`, `GET /api/user/recent`, `GET /api/user/account-status` (single fetch behind `useAccountStatus()` — returns ageConfirmedAt + per-document `*_version_accepted` + `deletion_requested_at` + `isAdmin` + workspace fates from `planAccountDeletion`).

**Privacy / account lifecycle (login required):** `POST /api/user/onboarding/accept` (writes Privacy + ToS + age via `applyOnboardingAcceptance` in one update), `POST /api/user/dpa/accept` (workspace-owner-only DPA acceptance), `POST /api/user/delete` (flips `deletion_requested_at`, audits, fires "deletion scheduled" email), `POST /api/user/delete-cancel` (one path segment — NOT `/delete/cancel`; nulls the column + audits `account.delete_cancelled`). Hard purge is async via `accountDeletionSweep.ts`, NOT inline.

**Data export (login required):** `POST /api/user/data-export` (enqueues a `data_export_jobs` row, audits `account.export_requested`; rate-limited), `GET /api/user/data-export/history` (lists user's recent jobs with status + S3 download URL when `ready`). The worker (`dataExportWorker.ts` plugin) drains queued rows; expiry sweeper flips `ready` → `expired` past 7-day TTL.

**Consent / cookies (no session — anon-id-keyed):** `GET /api/consent?anonId=…` (returns latest row for the anon-id), `POST /api/consent` (append-only insert; carries optional `userId` for post-login bridge). The `markoto-anon-id` cookie is the consent identity, NOT the user.

**Abuse reporting:** `POST /api/abuse-reports` (public, DSA Art.16 notice: `contentUrl`, `category`, `body`, `reporterName` + `reporterEmail` (optional for `csam`), `goodFaith: true`, `locale`; signed in 10/user/hour; anonymous needs the anonymous gate on + `altcha` (purpose `abuse-report`) + 5/hour, 20/day per client key; receipt recorded in `moderation_notices`; best-effort operator email).

**Anonymous gate:** `GET /api/anon-gate/challenge?purpose=doc-create|abuse-report` (public, 60/client/min, `no-store`) → `{enabled, termsVersion, termsAccepted, challenge}`. Anonymous `POST /api/docs` needs `altcha` + `acceptTerms: true` (or the remembered-terms cookie) → else 403 `anon-gate/*`; 10/hour + 30/day per client key. See `server/AGENTS.md` → Anonymous gate.

**Admin (admin-only via `requireAdminUser`):** `GET /api/admin/abuse-reports` (triage queue with reporter + actioner joins via `aliasedTable`), `PATCH /api/admin/abuse-reports/:reportId` (status change → audit `abuse.actioned` / `.dismissed`; closing needs `decision: {action, rule, explanation}`, applies removal / restriction and sends the decision notice + statement of reasons — `utils/moderationDecision.ts`; the GET lists `decision` + `notices`).

**Legal documents (no session):** `GET /api/_internal/legal/:slug` (renders markdown from `content/legal/:slug/<locale>.md` with `{{controllerName}}` / `{{controllerAddress}}` / `{{privacyContactEmail}}` / `{{abuseContactEmail}}` / `{{governingLaw}}` substitution against `resolveLegalEntity()`), `GET /api/_internal/sub-processors` (renders `SUB_PROCESSORS` registry as JSON for the `/legal/sub-processors` page).

**Docs search (no session):** `GET /api/_internal/docs-search` — the docs search sections (`queryCollectionSearchSections('docs')`) for the Cmd-K modal in `layouts/docs.vue`, fetched by the browser when search is about to open (not part of the SSR payload). `Cache-Control: public, max-age=300`.

**Files:** `POST /api/upload/request` (doc must exist + `requireDocEditAccess` — workspace viewers refused even on open-edit docs; 60/user/min; reserves the pending `uploads` row against the per-user image quota atomically (409 `upload/storage-quota`); 120 s presigned PUT for the STAGING key `docs/{docId}/staging/{file}` with `content-type` in the SIGNED headers — the browser must send exactly the requested image type; the response's `key` is the final key), `POST /api/upload/confirm` (60/user/min; the key must match `docs/{docId}/{nanoid12}.{png|jpg|gif|webp}` AND resolve to the caller's own `uploads` row, else 404 with NO S3 call; then HEAD of the staging object — stored Content-Type must equal the requested type (415 `upload/content-type-mismatch`) and size the requested size (400 `upload/size-mismatch`) — copy to the final key, delete the staging key, `file-type` sniff of the copy, quota re-check (409 `upload/storage-quota`); any rejection deletes that validated key's objects + pending row only; double confirm is idempotent, concurrent ones 409 `upload/confirm-in-progress`. Never act on a client-supplied key without this row check: the bucket also holds backups), `GET /api/files/:docId/:fileId` (302 + `Cache-Control: private, no-store` → presigned GET, access-controlled; the presigned URL forces `response-content-type` from the extension + `inline` disposition, so an object's stored type is never what decides how it's served. Self-host: Traefik adds `nosniff` + a sandbox CSP on the `/<bucket>/` route)

**Import:** `POST /api/import` (DOCX/PDF/PPTX/XLSX/HTML/EPUB → markdown, 50MB, public)

**Workspaces (login required):** `POST /api/workspaces` (enforces per-user cap), `GET/PUT/DELETE /api/workspaces/:wsId`, `POST /api/workspaces/:wsId/members` (admin: creates a PENDING invite — 202 `{ok, invited}` for any address, 409 only for an existing member, 409 `workspace/invite-cap`, 429 per admin / per workspace; optional email with a single-use accept link), `GET /api/workspaces/:wsId/invites` + `DELETE /api/workspaces/:wsId/invites/:inviteId` (admin: open invites, revoke), `PATCH/DELETE /api/workspaces/:wsId/members/:userId`

**Invitations (invitee, login required):** `GET /api/user/invites` (open invites for the account's verified email), `POST /api/user/invites/:inviteId/accept|decline` (404 unless addressed to the caller's email and unexpired), `POST /api/user/invites/by-token` (`{token, action: 'accept'|'decline'}` from the email link `/invites/accept?token=…`; single-use).

**Workspace knowledge (login required + membership):**
- `POST /api/workspaces/:wsId/knowledge/upload-request` — admin/editor; rate-limited + cap-checked; mints a 120s presigned PUT for the staging key (`content-type` signed) + reserves Valkey inflight slots (one member ≤ half of the workspace's free slots, 409 `knowledge/too-many-pending`)
- `POST /api/workspaces/:wsId/knowledge/confirm` — only for an upload issued to the caller in this workspace (Valkey pending record, claimed once; 404 otherwise, no S3 call); HEAD staging + stored-type check (415 `knowledge/content-type-mismatch`) + copy to the final key + `file-type` magic sniff of the copy + advisory-locked cap recheck + row insert; kicks `processKnowledge` fire-and-forget; always releases inflight slots
- `GET /api/workspaces/:wsId/knowledge` — any member; returns items (sans `markdown_cache`) + aggregate usage/cap info
- `DELETE /api/workspaces/:wsId/knowledge/:knowledgeId` — admin or editor-who-uploaded; cascades chunks via FK + best-effort S3 delete

**AI providers — bring your own key (login required):** `GET /api/user/ai-providers` (key-free configs + instance-default flags + availability + URL policy + allowed presets), `PUT /api/user/ai-providers/:capability` (`chat|image|transcription`; SSRF policy → verification via LiteLLM → encrypt + save; 422 `ai-provider/url-refused` / `ai-provider/verify-failed` with `reason`, 400 `ai-provider/key-required`; rate-limited 20/10 min; audited `ai_provider.saved`), `POST /api/user/ai-providers/:capability/verify`, `DELETE /api/user/ai-providers/:capability` (audited `ai_provider.deleted`), `GET /api/ai/availability` (per capability `{available, source: user|instance|none, platformBilled}` + `chat.supportsVision` + `transcription.liveDictation` + `webTools: {search, fetch}` = whether the operator configured Staan / Jina). AI entry points (`/api/ai/prompt`, `trigger-ai`, `/api/ai/transcribe`) answer **409 `ai/provider-missing`** when the needed capability has no provider.

**Design from a document (login required):** `POST /api/themes/from-document/upload-request` (`{filename, size}`; 10/user/hour; vision chat provider required — 409 `ai/provider-missing` / `design-import/no-vision`; pdf/docx ≤ 20 MB; presigned PUT to a per-user staging key), `POST /api/themes/from-document/start` (`{uploadId}` → `{jobId}`; claims the caller's pending upload, one run per user, reads + deletes + sniffs the file, audits `design_import.started`, runs in the background), `GET /api/themes/from-document/jobs/:jobId` (owner only: phase/round, then `result` or `error.code`). See `server/utils/AGENTS.md` → Design from a document.

**AI (login required):** `POST /api/ai/prompt` (returns `{sessionId}`; also handles selection-scoped rewrites since phase 5 collapsed the separate rewrite path into this one), `POST /api/ai/abort` (initiator only, 403 otherwise), `GET /api/ai/sessions/:sessionId` (initiator only, 404 otherwise: prompt, phase + status text, latest `message_to_user` answer, pending confirmation — the private half of a session; awareness only carries the phase), `GET /api/ai/sessions/:sessionId/stream` (same gate; Server-Sent Events: `status` events with the GET's JSON on every change, `end` when finished — what the prompt bar uses; the GET is its polling fallback), `POST /api/ai/sessions/:sessionId/confirm` (`{confirmationId, allow}`, initiator only; 409 when no longer pending — answered or timed out = deny), `POST /api/ai/transcribe` (voice → text via Voxtral Mini Transcribe through LiteLLM; `{text, inaudible}`), `POST /api/ai/dictate/token` (mints 60s JWT for the dictation WS), `WS /api/ai/dictate` (live dictation relay — JWT auth via first message, NOT query string), `POST /api/docs/:docId/comments/:commentId/trigger-ai` (AI ↔ comment thread via `@ai` mention; the triggering message — `replyId`, else the parent — must be the caller's own and mention the AI, else 404; see `server/utils/agentic/AGENTS.md`)

**Billing mode:** every billing-only route below answers **404 `{ data: { code: 'billing/disabled' } }`** when `NUXT_BILLING_ENABLED` is off (the default) — checkout, portal and the Stripe webhook. `GET /api/billing/tiers`, `GET /api/billing/prices` and `GET /api/user/billing` keep working (limits are still real; everyone resolves to `free`).

**Paid-plans waitlist (public, IP-rate-limited):** `POST /api/waitlist` (`{email, locale?, consent: true}` → always `202 {ok:true}`; 404 `waitlist/disabled` unless billing off + `NUXT_PLANS_COMING_SOON`; 400 `waitlist/consent-required` / `waitlist/invalid-email`), `POST /api/waitlist/confirm` (`{token}` → 200 `{confirmed:true}` or 400 `waitlist/invalid-token`), `POST /api/waitlist/unsubscribe` (`{token}` → 200 `{unsubscribed:true}`, deletes the row, idempotent; works in every billing mode). Pages `/waitlist/confirm` + `/waitlist/unsubscribe` are the email-link targets.

**Billing (login required):** `POST /api/billing/checkout` — body `{plan: 'pro', interval?: 'month'|'year', currency?: 'eur'|'chf'}` (Team / Business → 400 `billing/workspace-plan`: bought per workspace; a customer who paid in one currency gets 409 `billing/currency-locked` for the other, `users.billing_currency`); price id from the lookup-key catalogue (`server/utils/stripePrices.ts`, 503 when missing). Dual outcome: no live subscription → Stripe Checkout Session `{url, sessionId}`; live subscription (paid-tier upgrade) → IN-PLACE price swap on the existing subscription via `server/utils/stripePlanChange.ts` (`always_invoice` proration + `error_if_incomplete`, never a second concurrent subscription) → `{updated: true, plan}`; same price → 409 (monthly ↔ annual is a swap). Stripe Tax opt-in via `NUXT_STRIPE_AUTOMATIC_TAX=1` (dashboard must have Stripe Tax activated first). `POST /api/billing/portal` (Stripe billing-portal session for plan management + downgrades). `GET /api/billing/tiers` (public — resolved tier-cap map). `GET /api/billing/prices` (public — `{currencies, prices: {eur|chf: {pro|team|business: {month, year}}}, source}`: `stripe` = live amounts from the catalogue (billing on), `planned` = `shared/config/pricing.ts` + `TIER_<PLAN>_PRICE_<EUR|CHF>[_YEAR]`).

**Workspace billing — Team / Business (WP3, workspace admins only: 404 non-member, 403 `billing/admin-required`):** `GET /api/workspaces/:wsId/billing` (subscription, seats used = members + open invites, pool limits, team + per-member AI spend from LiteLLM; works with billing off), `POST /api/workspaces/:wsId/billing/checkout` (`{plan: 'team'|'business', interval?, currency?, seats ≥ 3}`; no live subscription → Checkout on the workspace's own Stripe customer, `client_reference_id = workspace:<id>`, an `incomplete` placeholder row first; live → in-place price swap keeping the quantity; 409 `billing/seats-below-members` / `billing/currency-locked`), `POST …/billing/seats` (`{seats}`, never below members + open invites; more seats charged now pro rata — 402 `billing/payment-failed` changes nothing — fewer seats not credited; the pooled budget follows `changedSeatBudgetAdjust`). A new Checkout expires the workspace's other open subscription Checkouts first, `POST …/billing/portal`, `PATCH …/billing/members/:userId` (`{limitUsd: n}` / `{limitUsd: null}` = no member limit / `{default: true}`), `POST …/billing/topup` (`{pack}`, AI credits for an entitled workspace, its customer + currency). Personal AI credits: `POST /api/billing/topup` (`{pack: '10'|'25'|'50', currency?}`, Pro only → 409 `billing/topup-needs-plan`; one-time Checkout). Balances: `credits` in `GET /api/user/billing` and the workspace billing GET. Inviting into an entitled workspace whose seats are all taken → 409 `billing/seats-full` unless the body has `addSeat: true` (buys one seat first). Invites and seat changes of one pooled workspace are serialised (409 `billing/seats-busy` while another runs). `DELETE /api/workspaces/:wsId` cancels the subscription before deleting anything: 502 `billing/cancel-failed` (Stripe refused) or 409 `billing/subscription-active` (billing off, subscription still running) and nothing is deleted. Checkout / seats / portal answer 404 `billing/disabled` with billing off. `/api/ai/credits?workspaceId=` returns `attribution: 'workspace'` + `workspace: {teamBudgetUsd, teamSpendUsd, memberLimitUsd, memberSpendUsd, exhausted, teamExhausted}` for a member of an entitled workspace.

**Workspace single sign-on (WP14, admins; `server/utils/sso/AGENTS.md`):** `GET|PUT|DELETE /api/workspaces/:wsId/sso` (settings; PUT 409 `plan/feature-unavailable` without the `sso` plan feature, 400 `sso/invalid-settings` with `field`; never returns the client secret, the certificate body or the SCIM token), `POST …/sso/domains` / `POST …/sso/domains/:id/verify` (422 `sso/domain-unverified`, 409 `sso/domain-taken`) / `DELETE …/sso/domains/:id`, `POST|DELETE …/sso/scim-token` (token returned once). `POST /api/auth/sso/discover` (public: email → sign-in link, 404 `sso/no-connection`). Sign-in routes `/auth/sso/:id[/callback|/acs|/metadata]` and SCIM `/scim/v2/*` live under `server/routes/`. A member blocked by enforcement gets 403 `sso/required` + `loginUrl` (+ `canManageSso` for admins) from `GET /api/workspaces/:wsId`, and `ssoLoginUrl` in the denied `/token` answer.

**Workspace guests + usage (WP11):** `GET /api/docs/:docId/shares` (admins + editors of the doc's workspace, else 403 `share/not-allowed`: `{shares, guests}`), `PUT /api/docs/:docId/shares` (`{userId, access: 'view'|'edit'}`; 404 `share/not-a-guest`, 400 `share/invalid`; audited `doc.shared`), `DELETE /api/docs/:docId/shares/:userId` (audited `doc.unshared`, kicks the guest's connection), `GET /api/user/shared-documents` (the caller's documents as a guest), `GET /api/workspaces/:wsId/usage` (admins: per person documents / shared documents / knowledge files + bytes / image bytes / pooled AI spend; 403 `usage/admin-required`). `POST …/members` takes `role: 'guest'` (409 `plan/feature-unavailable`, 409 `workspace/guest-cap`); `GET /api/workspaces/:wsId` returns `guests: {available}` for admins.

**Workspace brand kit (WP10; `server/utils/AGENTS.md` → Brand kit):** `GET /api/workspaces/:wsId/brand` (members: fonts, logos, `available`, `canManage`, limits), `POST …/brand/fonts` (admins, multipart `file` + `licence=true` + optional `family` / `weight` / `style`; 422 `brand/font-refused` + `reason`, 409 `brand/family-built-in` / `brand/font-exists` / `brand/too-many-fonts`, 400 `brand/licence-required`), `POST …/brand/images` (admins, multipart `file`, PNG / JPEG / WebP by bytes → else 415 `brand/image-type`), `DELETE …/brand/assets/:assetId` (admins, also without the plan), `GET …/brand/files/:file` (members, previews), `PUT …/brand/lock` (`{locked}`; locking needs the plan + a workspace design → 409 `brand/no-design`), `POST …/brand/design-from-doc` (`{docId}` of the workspace → the workspace default theme, own uploads left out), `GET|POST /api/workspaces/:wsId/templates`, `PATCH|DELETE …/templates/:id`, `POST …/templates/:id/documents` (`{title?}` → a private copy owned by the caller; admins + editors). `GET /api/docs/:docId/brand/:file` (public route, `decideFileAccess` + the asset must be in the doc's workspace). `/token` and `/meta` return `brandKit: {fonts, lockedTheme}`; `GET /api/workspaces/:wsId` returns `brandKit: {available, inUse}` + `brandLocked`. Changes other than with the plan feature → 409 `plan/feature-unavailable`; changes are audited (`workspace.brand_asset_*`, `.brand_lock_changed`, `.template_*`).

**Workspace audit log (WP15, admins; plan feature `auditLog` → else 409 `plan/feature-unavailable`):** `GET /api/workspaces/:wsId/audit` (`?before=<id>&action=<prefix>&from=&to=` → `{events, nextBefore, retentionDays}`), `GET /api/workspaces/:wsId/audit/export?format=csv|jsonl` (attachment, ≤ 100 000 rows → 413 `audit/too-many-rows`, 10 / admin / hour, audited).

**Webhooks (no session — signature-verified):** `POST /api/webhooks/stripe` — verifies `Stripe-Signature` against `NUXT_STRIPE_WEBHOOK_SECRET`, then dispatches via `dispatchStripeEvent`. Replay-protected via `processed_webhook_events` (atomic INSERT ON CONFLICT DO NOTHING short-circuits replays). Out-of-order events (`subscription.*` / `invoice.*` arriving before the binding `checkout.session.completed`) are stashed in `pending_stripe_events` and drained in receive order on the eventual checkout. Always responds 200 to Stripe even on internal handler errors when the row is already deduped, so Stripe stops retrying. See `server/utils/AGENTS.md`.

Auth guard: see `server/AGENTS.md` for whitelist conventions.

**Audit-log readers:** none in user-facing UI. `appendAuditEvent` is fire-and-forget from privileged endpoints (workspace delete, member role change, member removal, account-deletion lifecycle, abuse-report lifecycle, admin grant/revoke, consent recorded, policy accepted) and several sweepers. The `/api/admin/abuse-reports` endpoints DO read audit indirectly (the actioner column is FK'd to `users` so the join surfaces who triaged); a broader forensic admin UI is future work — when added, gate on `requireAdminUser` from `server/utils/adminAccess.ts`.
