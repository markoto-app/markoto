# app/utils

Client-side utilities for the editor pane and preview pipeline.

## Preview Rendering & PDF Export

Right pane shows discrete A4/Letter pages inside a sandboxed, **opaque-origin** srcdoc iframe (see "Preview isolation" below). PDF has TWO paths: client-side (the historical one — same pipeline in a hidden iframe + `window.print()`) and **server-side via the renderer sidecar** (Phase 5). Both share the same theme-CSS + markdown pipeline; only the host shell differs.

**Shared pipeline (`renderMarkdown.ts` → `shared/utils/themeToCss.ts` → `app/composables/usePagedPreview.ts` for client / `app/pages/_internal/render/[docId].vue` for server):**
1. `renderMarkdown.ts` — singleton markdown-it, sanitised by `sanitizeHtml.ts` (DOMPurify with the tag/attr/URI allowlist + an inline-`style` property allowlist: DOMPurify doesn't parse CSS, so `{style=…}` / KaTeX styles go through `filterInlineStyle`). Plugins lazy-imported inside `init()`. Pipeline: core + task-lists + emoji + footnote + Batches 1–3 + custom pagebreak rule + comment plugin. Always emits `language-${lang}` class so the mermaid detector finds `pre code.language-mermaid`.
2. `transformFootnotesForPagedMedia(html)` lifts footnote `<li>` from end-of-doc `<section>` to inline `<span class="footnote">` at the ref site — required for paged.js `float: footnote`.
3. `shared/utils/themeToCss.ts` compiles `DocTheme` into the full stylesheet — `@page`, margin boxes, `.paged-doc` body, headings, TOC (with `target-counter` page numbers), page-break, column-span spanners.
4. `app/utils/composeFinalHtml.ts` is the single point that assembles the final HTML (cover + markdown body + drop cap) and **sanitises the composed result again** (`sanitizeRenderedHtml`) — the cover is built from theme values, and the theme can arrive over Y.js without HTTP validation. Live preview, browser print and the server-rendered page all consume it (browser-only: DOM + DOMPurify). The drop cap (`dropcapWrap.ts`) works on parsed DOM, never regexes over the HTML string.
   **Render-time theme checks (all three consumers):** `isValidTheme` (invalid → `defaultTheme`; the render page imports it lazily in `onMounted` because zod wedges its SSR) + `themeImagesForDoc(theme, docId)` (`shared/utils/themeImages.ts`), which blanks `brand.logoUrl` / `header|footer.imageUrl` unless empty, a bundled `/markoto-logos/*` asset or `/api/files/<thisDoc>/<file>.<png|jpg|gif|webp>`. The schema enforces the same shape; `meta.put` additionally 400s `theme/image-not-in-doc` for another doc's upload; saved/workspace/AI base themes are adapted (foreign images cleared), duplicates rewrite the doc id. `themeToCss` serialises every generated string via `cssString` (CSSOM rules: control chars + newline hex-escaped) and only emits shape-valid image URLs.
5. **Live preview** — `app/composables/usePagedPreview.ts` mounts a persistent srcdoc iframe (`sandbox="allow-scripts"`) built by `buildPreviewSrcdoc()` (`app/utils/previewFrame.ts`). Parent posts a `render` message (250ms debounce; built by `buildRenderMessage`: composed HTML + theme CSS + fonts + hljs URL/SRI + `mermaidConfig` JSON + document `locale`). Iframe decodes images, renders mermaid → `<img data:svg>` (mermaid runs INSIDE the iframe), runs paged.js (with the pagination handlers, below), swaps each diagram `<img>` for its inline SVG, and posts back `{type:'paginated', pageCount}`. All links are intercepted (fragment → scroll, anything else inert) so the sandboxed frame never navigates.
6. **Client-side PDF** — `printPdf.ts` — a hidden iframe running the SAME bootstrap (`sandbox="allow-scripts allow-modals"`), `render` message with `print: true` → paginate → `window.print()` inside the iframe → `print-done` on `afterprint`. 30s pagination timeout (cleared once paginated; the dialog may stay open), 10-min lifetime cap. The bootstrap's `@media print` block strips the preview chrome.
7. **Server-rendered PDF / PNG (Phase 5)** — `GET /api/docs/:docId/pdf` mints a single-use render token, calls the renderer sidecar (Playwright in a separate container), which navigates to `app/pages/_internal/render/[docId].vue?t=<token>`. That page SSRs via `server/api/_internal/render-bootstrap.get.ts`: replays Y.js to materialise the markdown body, runs the same pipeline above, returns headless-rendered PDF/PNG bytes. The page never connects to Hocuspocus — Y.Doc state is server-rendered. Failure mode: the API endpoint is the source of truth; if the renderer is down the request 503s and the UI surfaces the error (no fallback to client-side paged.js — they're not byte-identical and silently swapping is worse than a clear failure).

**Why the server path even with a perfectly good client path:** AI tools (`view_pages`, page-screenshot consumers) need a deterministic byte-stable render the model can ingest. A user's local fonts / display zoom / browser would otherwise produce different paged-media output per user. The renderer sidecar gives one canonical render per `(doc, theme, viewport)`.

**Why iframe:** paged.js mutates global head styles + `:root` vars and re-paginates on every call. Running on the host page caused unrecoverable layout contamination. Use CSS `zoom` (not `transform: scale`) for responsive shrinking — zoom shrinks layout box; scale doesn't.

**paged.js quirks:** Polisher only processes `@page` rules from `stylesheets` argument — pass `[{ 'theme.css': cssText }]`. Margin boxes are siblings of `.paged-doc`, not descendants; CSS custom properties don't propagate up. Bake `{title}`/`{date}` into the CSS string directly.

**Preview isolation (security batch B5).** The preview + print iframes have NO `allow-same-origin`: they run in an opaque origin, so a script injection in rendered content can't touch the app's cookies, storage, DOM or same-origin APIs. Consequences, all handled in `app/utils/previewFrame.ts`:
- **postMessage only, typed + checked both ways.** Parent → iframe: `render`, `color-mode` (the iframe can't read the parent's `dark` class; `usePagedPreview` forwards it from a MutationObserver, initial value baked into the srcdoc), `zoom`. Iframe → parent: `iframe-ready`, `paginated`, `iframe-error`, `print-shortcut`, `print-done`, `zoom-state`, `zoom-request`, `zoom-gesture` (see "Preview zoom" below). Parent accepts only `e.source === iframe.contentWindow && e.origin === 'null'` + per-type shape (`parseFrameMessage`); the iframe accepts only `e.source === window.parent && e.origin === <parent origin>` (substituted into the srcdoc) and posts to that origin only.
- **Images.** The iframe's requests are cross-site → no session cookie. Exact own-upload URLs (`/api/files/<thisDoc>/<fileId>`, `ownUploadFileId`) get `?token=<file-access JWT>` — `<img src>` in the HTML (`attachOwnUploadTokens`), header/footer images (`themeToCss` `imageUrl`), custom-CSS url()s (sanitizer `fileUrl`); never links or other URLs that merely contain the path (same rule as the render page's `renderFileTokens.ts`). The token is minted by `GET /api/docs/:docId/file-token` (same `decideFileAccess` gate as `/api/files`; password visitors send their doc JWT as Bearer — `useDocument().getDocJwt`), 15 min, cached + refreshed by `createFileTokenSource`. `/api/files` is the only endpoint that accepts the `file-access` scope. `/api/files` responses carry `Cross-Origin-Resource-Policy: cross-origin` (everything else `same-site`, `server/plugins/csp.ts`) — CORP same-site would block the opaque-origin `<img>`.
- **CSP.** The srcdoc inherits the page's CSP: its inline scripts carry the page nonce (`currentCspNonce()` reads `script.nonce`), no inline `on*=` handlers. `'self'` in the inherited policy still means the app origin — which is how the `/vendor/` scripts, styles and fonts pass.
- **Cost:** keystroke → repaint within noise of the same-origin version (welcome ×10, 31 pages: p50 ~1.25 s vs ~1.30 s; 48-page doc with images/Mermaid/math: p50 ~7.4 s both, incl. the 250 ms debounce), browser memory +1–3 %. Reproduce with `scripts/measure-preview-perf.ts` against the flow test stack.

**Preview zoom + "All pages" overview.** Fit width (default; never enlarged past 100 %), fixed steps 50–200 % (`PREVIEW_ZOOM_STEPS`), free factor 30–300 % from pinch / Ctrl+wheel, and `overview` (pages wrap side by side, thumbnails ≥ 140 px — ≥ 96 px on phones — at most half size). Three layers: `app/utils/previewZoom.ts` (pure: setting type, zoom in/out walk — below 50 % comes the overview, from the overview zoom-in = fit —, shortcut matcher, localStorage key `markoto:preview-zoom` in try/catch, per browser, never per document), `app/composables/usePreviewZoom.ts` (shared `useState` — the pane pill `components/preview/ZoomControl.vue`, the mobile view-mode bar's compact button and View › Zoom all drive it; `command.seq` tells `usePagedPreview` to post a `zoom` message; `usePreviewZoomMenu` builds the dropdown items), and `app/utils/previewZoomFrame.ts` — the engine INSIDE the iframe, self-contained and inlined via `__PREVIEW_ZOOM_SCRIPT__` like the pagination handlers (`tests/dom/previewZoomFrame.test.ts` evaluates the string). The engine only sets `--page-zoom` (CSS `zoom`) + `--overview-gap` on `.pagedjs_pages` and `zoom-scale` / `zoom-overview` classes on `<html>`; it never re-paginates (`reapply(true)` runs after each render's swap, remeasuring the natural page width at zoom 1). Reading position: the page under the viewport centre (or the gesture point) keeps the same spot after a change; an overview click (`zoom-request` `page`) opens that page at fit width, top of the view. The pull-back / push-in is one Web Animations transform on `#mount` (rect of the anchor page before → after, 520 ms; 200 ms between steps; none under `prefers-reduced-motion`), `html.zoom-animating` hides overflow meanwhile. Gestures are applied live in the frame (rAF-batched) and reported once (`zoom-gesture`); the parent stores them without echoing, or switches to the overview when pinched past the minimum. `html { touch-action: pan-x pan-y }` + `gesturestart` preventDefault keep pinch inside the preview. Shortcuts: inside the frame (focus there) the engine forwards Ctrl/Cmd `=`/`-`/`0` as `zoom-request`; with focus elsewhere but the pointer over the pane, `PreviewPane` handles them (the editor binds none). The print block resets zoom, layout and transform (`zoom: 1 !important`, `display: block`, `#mount { transform: none }`); `printPdf` never sends `zoom`, the server renderer / `view_pages` don't use this bootstrap.

**Third-party browser assets are served from our own origin, SRI-locked.** paged.js, KaTeX (stylesheet + woff2 fonts), the highlight.js themes, Mermaid and the web fonts load from `/vendor/` — never from jsDelivr / Google Fonts — so visitors' browsers and the renderer request nothing from a third party and an air-gapped self-host still renders. `modules/vendor-assets.ts` copies them out of the pinned npm packages at every `nuxt dev` / `build` / `prepare` (generator + checks: `scripts/lib/vendorAssets.ts`; output `node_modules/.cache/markoto-vendor-assets`, registered as a Nitro public-asset dir). Paths are versioned (`/vendor/<pkg>@<version>/…`), served `immutable`; the per-family font stylesheets `/vendor/fonts/<slug>.css` are the one unversioned name (`no-cache`, `server/utils/vendorAssetHeaders.ts`). Version + URL + SRI live in `shared/utils/{pagedjsAssets,katexAssets,hljsAssets,mermaidAssets}.ts` (`*_URL` + `*_SRI`; hljs: `hljsTheme(theme) → {url, sri}` per theme); the bytes are the npm package's, so the hash is unchanged from the jsDelivr days. **Bump:** change package.json + the `*_VERSION` constant, recompute with `openssl dgst -sha384 -binary node_modules/<pkg>/<file> | openssl base64 -A` — the build refuses to start while version or hash disagree (`tests/unit/vendorAssets.test.ts` pins the same). Mermaid is the single-file IIFE build (`mermaid.min.js`, devDependency, injected as `<script integrity crossorigin>`) — the ESM build's `import()` + ~100 lazy chunks can't be SRI-checked. Parent-context mermaid (server render page only) lives in `app/utils/mermaidLoader.ts`. The opaque-origin iframe sees our origin as cross-origin: `/vendor/*` answers with CORP `cross-origin` + `Access-Control-Allow-Origin: *`, and every SRI tag keeps `crossorigin="anonymous"` (SRI only fires in CORS mode; fonts are CORS requests anyway). Workbox: `/vendor/**` is NOT precached (~12 MB); the SW runtime-caches it (CacheFirst; font stylesheets StaleWhileRevalidate) for app-shell requests — the sandboxed iframes aren't SW clients and use the HTTP cache.

**Web fonts** (`shared/utils/themeFonts.ts`): 23 self-hosted families from exact-pinned `@fontsource-variable/*` / `@fontsource/*` packages — the 20 picker fonts + JetBrains Mono, IBM Plex Mono, Fraunces (app shell + presets). woff2 only, normal + italic, every unicode-range subset the package ships (a browser downloads only the subsets/styles a page uses), `font-display: swap`, renamed to the theme's family name (`'Inter'`, not `'Inter Variable'`), licence next to the files. `themeFontsImport(theme)` emits one `@import url('/vendor/fonts/<slug>.css')` per family the theme uses; a family outside the registry renders in the fallback stack. The app shell links Inter / JetBrains Mono / Fraunces the same way (`app.vue`); the theme panels link the picker fonts' stylesheets (only @font-face rules — files download when an item shows text in them). `@nuxt/fonts` is disabled (`ui.fonts: false` in `nuxt.config.ts`). Adding a family: install the Fontsource package exact, add a `font(...)` line.

**Theme system (`shared/types/theme.ts:DocTheme`):** Per-doc JSONB in `documents.theme`, mirrored to `ymeta.theme`. Validated by `shared/utils/themeValidation.ts`. Editor panel: `ThemeEditorPanel.vue` (16 accordion sections). Presets in `shared/utils/themePresets.ts` (Modern, Academic Paper 2-col, Tech Report, Business Report, Novel, Newsletter). Font picker from `shared/utils/themeFonts.ts` (20 self-hosted fonts, see above). Header/footer tokens: `{title}`, `{date}`, `{page}`, `{pages}` — inserted at cursor via `data-slot`/`data-position`. User-saved themes shipped (CRUD via `/api/user/themes`).

**Custom CSS (`theme.customCss`, optional, ≤ 64 KB):** documents only — appended LAST by `themeToCss` via `runtime.customCss` (the sanitizer's `CustomCssResult`, never the raw string; `themeToCss` never reads `theme.customCss`). One sanitizer, `shared/utils/customCss.ts` (css-tree parser/walker/generator subpaths, exact-pinned; types for the subpaths in `shared/types/css-tree-subpaths.d.ts`), used at WRITE time (`meta.put`, saved themes, workspace default, AI/MCP `update_theme` → 400 `theme/custom-css-invalid` + `data.issues[{code,message,line,column}]`) AND at RENDER time in all three consumers (`usePagedPreview`, `printPdf`, `_internal/render/[docId].vue`) — mandatory, `ymeta.theme` is writable over Y.js. Browser code loads it lazily through `app/utils/customCssLoader.ts` (~23 KB gzip; docs without custom CSS never fetch it). Checks run on the AST with decoded identifiers: at-rule allowlist (`@media/@supports/@page`+margin boxes/`@keyframes/@container/@layer/@font-feature-values`; `@charset` dropped silently), no `expression()`/`behavior`/`-moz-binding`/`javascript:`/`vbscript:`, no `var()`/`env()`/`attr()` inside image functions (`image-set`/`image`/`cross-fade`/`src`/`element` — the substituted value would skip the URL check), nesting > 32 levels or a parser exception fails closed (empty CSS + `syntax` issue; `sanitizeCustomCssForRender` also catches and renders without custom CSS), `url()` + url-taking functions (`image-set`, `image`, `cross-fade`, `src`) only to `/api/files/<thisDocId>/<fileId>` (relative or allowed app origin → normalised) or base64 raster `data:image/*` (no SVG), custom-property values parsed too, unparseable `Raw` chunks dropped unless inert. Output = css-tree re-serialisation with every `<` escaped as `\3c ` (no `</style`, `<!--`, `<script`). The render page maps own-upload URLs through `fileUrl` (adds the file-access `?token=` for confirmed uploads) and preloads `result.urls`. Applying a saved theme / creating a doc from one / AI base themes drop rules pointing at another doc (`adaptCustomCssToDoc`); built-in presets keep the doc's CSS; duplicates rewrite the doc id (`withThemeDocId`). UI: `components/document/ThemeCustomCssSection.vue` (CM6 + `@codemirror/lang-css`, mounts on intersection, emits only valid CSS). The sync-server keeps a SHA-256 of `ymeta.theme` (not the JSON) as its `theme.changed` baseline in Valkey.

## Documents at scale (charts, pagination, tables, cover)

What makes a 15-page report paginate and look like one document. Same code in all three render paths; the render harness pattern (`renderMarkdown → transformMermaid → composeFinalHtml → themeToCss → paged.js`, then Playwright `page.pdf`) reproduces the server PDF outside the app.

- **Document language drives in-document text** (`shared/utils/documentLocale.ts`, `documentTexts(theme, language)`): the cover date + `{date}` token (`theme.cover.date` `YYYY-MM-DD`, empty/absent = today, written out per language: `29 October 2026` / `29. Oktober 2026`; plain `en` uses day-month-year), the TOC title (sentence case: Contents / Inhalt / Sommaire …) and chart number formats. Follows `ymeta.language` (free text tolerated, unknown → `en`), never the viewer's UI locale. Consumers: `usePagedPreview` (+ `PreviewPane` `language` prop), `printPdf` (`language`), the render page (bootstrap `language`). `composeFinalHtml` takes the formatted `date`. `cover.date` is optional in the schema (old themes stay valid); `themeValidation` and the ymeta contract share the schema; AI `update_theme` accepts `cover.date`.
- **Mermaid config** (`shared/utils/mermaidConfig.ts`, `buildMermaidConfig(theme)`): font = body font always; label size = body size, floor 11px (≈8pt); xy-charts drawn exactly one text column wide (`textColumnWidthPx`) so their text isn't scaled; flowcharts with tighter spacing; pie text larger (pies are shown smaller, see below); root `htmlLabels: false` (plain SVG `<text>`, no `<foreignObject>`); `securityLevel: 'antiscript'` (the iframe re-forces it). `mermaid.theme === 'document'` (the new default, enum value added) = Mermaid `base` + themeVariables from brand/heading/text/secondary/paper and an accent-led categorical palette (`shared/utils/themeColors.ts`, OKLCH, every entry dark enough for white slice labels); xy-chart bars get a lighter accent so a line in heading ink reads over them. Built-in themes keep Mermaid's colours (explicit choice wins).
- **Charts in the page's font: `<img>` for layout, inline SVG after.** An SVG loaded as an image can't use web fonts, and an inline SVG gets split by paged.js. So diagrams paginate as `<div class="mermaid mermaid-<kind>"><img data:svg width height>` and are swapped for the SVG after `preview()` resolves (`inlineMermaidSvgs` in `mermaidLoader.ts` — DOMPurify SVG profile, since the render page runs in the app origin; the iframe copy only drops `<script>` because it is the opaque-origin sandbox). Same intrinsic size + one CSS rule for `img` and `svg` → nothing reflows. A diagram still containing `<foreignObject>` stays an image. Before rendering, the body font is loaded (`document.fonts.load`, bounded) so Mermaid measures labels in it; the render page now injects the font import BEFORE `transformMermaid`. `finishMermaidSvg` sets pixel width/height from the viewBox and formats pie legend values (`[3320]` → `3,320`) and xy-chart axis ticks for the document locale; `thinAxisTicks` thins a crowded numeric axis to ≤ 8 labels on a nice step (Mermaid asks d3 for ~10 ticks and has no tick-count option, e.g. 15 labels for 0–7000). User CSS that targets `.mermaid img` only applies during layout — target `.mermaid > svg` too.
- **Diagram sizing** (themeToCss `mermaidBlock`): natural size, `max-width: 100%`, `max-height` 45% of the text area; pies (`.mermaid-pie`) ≤ 85mm.
- **Pagination handlers** (`app/utils/pagedHandlers.ts`, a paged.js `Handler` registered once per window): `onOverflow` moves the break so that (1) headings stay with the next block (keep-with-next; paged.js 0.4.3 ignores `break-after: avoid-page`), (2) anything with computed `break-inside: avoid` moves whole, (3) tables break between rows only, with at least 3 body rows on each side of a split — more rows are carried over, or the table moves whole (`rowsFrom` reads `chunker.source`), (4) a paragraph never leaves one line behind. Every move requires other content before it on the page (no loops / empty pages). `renderNode` clones the source `<thead>` into a table continued on a new page (`markoto-repeated-thead`, data-refs stripped). **Delivery:** the function is self-contained and the iframe receives its `toString()` as a nonce'd inline script (`PAGED_HANDLERS_SCRIPT`, `__PAGED_HANDLERS_SCRIPT__` placeholder, function replacer) — keep it free of imports/module references; `tests/dom/pagedHandlers.test.ts` evaluates the string.
- **Break CSS:** headings `break-after: avoid-page; break-inside: avoid`; `img, pre, blockquote` avoid; only SHORT tables (≤ 12 body rows, `table:not(:has(tbody tr:nth-child(13)))`) avoid — long tables split with repeated headers.
- **Editorial cover:** short accent rule above the title, hairline above author/date, and a full-bleed accent band along the top edge when there is no logo (`markoto-cover--no-logo`, set by `coverHtml.ts`).
- **Table attributes:** `{.class}` on the line right under a table applies to the table (`markdownTableAttrs.ts` turns the attrs-only trailing row markdown-it parsed back into the paragraph `@mdit/plugin-attrs` expects). The blank-line form works too.
- **Footnote separator:** `transformFootnotesForPagedMedia` also removes markdown-it-footnote's `<hr class="footnotes-sep">` (it printed as a stray rule at the end).

## Markdown Comments

`<!-- ... -->` comments are stripped from the rendered preview/PDF/share view but stay in the markdown source. Two markdown-it rules in `renderMarkdown.ts:commentPlugin`:

- **Block rule** — a line (or multi-line range) whose only non-whitespace content is a comment is consumed entirely. Closes on the line containing `-->`; trailing real content on the close line aborts the match (lets the inline rule handle it).
- **Inline rule** — `<!-- ... -->` mid-paragraph is stripped in place; surrounding prose flows around the gap.

Pagebreak (`<!-- pagebreak -->`) wins by registration order — the pagebreak rule runs first and short-circuits its exact pattern.

**Toolbar + menu:** `toggleComment` in `editorCommands.ts` wraps the selection in `<!-- ... -->` (toggleWrap-style: empty → drops `<!-- | -->` cursor inside; selection → wraps + re-selects inner; pre-wrapped → unwraps). Surfaced as `i-lucide-message-square-dashed` button in `EditorToolbar.vue` (after page-break + TOC) and as an "Comment (hidden from preview)" item in the `EditorMenuBar.vue` Insert menu.

**AI vocabulary:** `server/utils/agentic/markdownReference.ts` documents the syntax so the AI knows it can leave private notes for the writer. Templates use this heavily — every section in the recipe / business-plan / academic-paper / etc. templates has a `<!-- ... -->` brief telling the AI (or the user) what to write there.

**Audit script** (`scripts/audit-markdown-pipeline.mjs`) covers 11 cases including pagebreak precedence, multi-line blocks, mid-paragraph stripping, unterminated fallback (escapes to literal `&lt;!--`), code-fence preservation. Run before adding any syntax claim to `markdownReference.ts`.

## Gotchas

- **`markdown-it-emoji`** needs `.full`: `const emoji = (mod as any).full || (mod as any).default || mod`.
- **`highlight.js` CSS** must be dynamically imported inside `initMd()` — otherwise code blocks are all white.
- **Footnotes need `transformFootnotesForPagedMedia()`** — markdown-it-footnote puts all footnotes at end of doc; paged.js `float: footnote` needs inline `<span>` at the ref site.
- **Iframe bootstrap lives in `pagedPreviewIframe.html`, not a template literal** — imported as a raw string via `?raw` in `previewFrame.ts`. Placeholders (`__CSP_NONCE__`, `__PARENT_ORIGIN__`, `__INITIAL_DARK__`, vendored-asset URLs + SRIs) substituted by `buildPreviewSrcdoc`; `tests/unit/pagedPreviewIframe.test.ts` pins the contract (nonce on every inline script, no inline handlers, no `parent.document`, origin-checked messaging).
- **Never give the preview/print iframe `allow-same-origin`** — and never read `iframe.contentDocument` / call into `contentWindow` from the app or from tests (Playwright: `frameLocator('iframe')` / `EditorPage.previewRoot()`). `tests/nuxt/previewFrame.test.ts` + `tests/e2e/flows/preview-isolation.spec.ts` pin it.
- **Mermaid labels** — `htmlLabels: false` (root + flowchart) so diagrams are pure SVG `<text>`: they serialise as XML, survive the SVG sanitiser and inline cleanly. Label boxes are only right when the body font is loaded before `mermaid.render` (both paths do it); `overflow: visible` on the diagram keeps a slightly short label from being clipped.
- **srcdoc links navigate the iframe** — the bootstrap captures every `<a href>` click: `#…` → `preventDefault + target.scrollIntoView()`, anything else → `preventDefault` (the sandboxed preview must never navigate itself).
- **`html: false` doesn't block manually pushed tokens** — custom block rules that call `state.push('html_block')` render verbatim regardless. Use this for controlled HTML emission.
- **TOC: anchor plugin must load BEFORE toc plugin** — `markdown-it-anchor` assigns IDs; `markdown-it-toc-done-right` reads them. Share one `slugify`.
- **KaTeX inline `style`** — DOMPurify must allow `style` attribute; add `math`/`semantics`/`mrow`/etc. to the allowlist. Every `style` value is filtered to `ALLOWED_STYLE_PROPERTIES` in `sanitizeHtml.ts` (no `url()`, `var()`, quotes/escapes, `position` other than relative/static, viewport units). If KaTeX starts emitting a new property, add it there — `renderMarkdownXss.test.ts` compares our output against raw KaTeX.
- **`@mdit/plugin-img-size` in our stack does NOT parse `=WIDTHxHEIGHT`** — despite the package's readme. Use `@mdit/plugin-attrs` syntax: `![alt](url){width=50%}`. The audit script catches mis-documented syntaxes.
- **CSS `zoom` not `transform: scale`** — `scale` leaves layout box full-size and overflows; `zoom` shrinks both.
- **Markdown comments via custom block + inline rules (NOT via `html: true` + DOMPurify-strip).** Flipping `html: false` → `html: true` to let DOMPurify strip `<!--...-->` would reopen XSS surface. Custom rules give us comment stripping without changing the html-escape gate.
