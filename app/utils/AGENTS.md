# app/utils

Client-side utilities for the editor pane and preview pipeline.

## Preview Rendering & PDF Export

Right pane shows discrete A4/Letter pages inside a sandboxed, **opaque-origin** srcdoc iframe (see "Preview isolation" below). PDF has TWO paths: client-side (the historical one — same pipeline in a hidden iframe + `window.print()`) and **server-side via the renderer sidecar** (Phase 5). Both share the same theme-CSS + markdown pipeline; only the host shell differs.

**Shared pipeline (`renderMarkdown.ts` → `shared/utils/theme/themeToCss.ts` → `app/composables/preview/usePagedPreview.ts` for client / `app/pages/_internal/render/[docId].vue` for server):**
1. `renderMarkdown.ts` — singleton markdown-it, sanitised by `sanitizeHtml.ts` (DOMPurify with the tag/attr/URI allowlist + an inline-`style` property allowlist: DOMPurify doesn't parse CSS, so `{style=…}` / KaTeX styles go through `filterInlineStyle`). Plugins lazy-imported inside `init()`. Pipeline: core + task-lists + emoji + footnote + Batches 1–3 + custom pagebreak rule + comment plugin. Always emits `language-${lang}` class so the mermaid detector finds `pre code.language-mermaid`.
2. `transformFootnotesForPagedMedia(html)` lifts footnote `<li>` from end-of-doc `<section>` to inline `<span class="footnote">` at the ref site — required for paged.js `float: footnote`.
3. `shared/utils/theme/themeToCss.ts` compiles `DocTheme` into the full stylesheet — `@page`, margin boxes, `.paged-doc` body, headings, TOC (with `target-counter` page numbers), page-break, column-span spanners.
4. `app/utils/preview/composeFinalHtml.ts` is the single point that assembles the final HTML (cover + markdown body + drop cap) and **sanitises the composed result again** (`sanitizeRenderedHtml`) — the cover is built from theme values, and the theme can arrive over Y.js without HTTP validation. Live preview, browser print and the server-rendered page all consume it (browser-only: DOM + DOMPurify). The drop cap (`dropcapWrap.ts`) works on parsed DOM, never regexes over the HTML string.
   **Render-time theme checks (all three consumers):** `isValidTheme` (invalid → `defaultTheme`; the render page imports it lazily in `onMounted` because zod wedges its SSR) + `themeImagesForDoc(theme, docId)` (`shared/utils/theme/themeImages.ts`), which blanks `brand.logoUrl` / `header|footer.imageUrl` unless empty, a bundled `/markoto-logos/*` asset or `/api/files/<thisDoc>/<file>.<png|jpg|gif|webp>`. The schema enforces the same shape; `meta.put` additionally 400s `theme/image-not-in-doc` for another doc's upload; saved/workspace/AI base themes are adapted (foreign images cleared), duplicates rewrite the doc id. `themeToCss` serialises every generated string via `cssString` (CSSOM rules: control chars + newline hex-escaped) and only emits shape-valid image URLs.
5. **Live preview** — `app/composables/preview/usePagedPreview.ts` mounts a persistent srcdoc iframe (`sandbox="allow-scripts"`) built by `buildPreviewSrcdoc()` (`app/utils/preview/previewFrame.ts`). Parent posts a `render` message (250ms debounce; built by `buildRenderMessage`: composed HTML + theme CSS + fonts + hljs URL/SRI + `mermaidConfig` JSON + document `locale`). Iframe decodes images, renders mermaid → `<img data:svg>` (mermaid runs INSIDE the iframe), runs paged.js (with the pagination handlers, below), swaps each diagram `<img>` for its inline SVG, and posts back `{type:'paginated', pageCount}`. All links are intercepted (fragment → scroll, anything else inert) so the sandboxed frame never navigates.
6. **Client-side PDF** — `printPdf.ts` — a hidden iframe running the SAME bootstrap (`sandbox="allow-scripts allow-modals"`), `render` message with `print: true` → paginate → `window.print()` inside the iframe → `print-done` on `afterprint`. 30s pagination timeout (cleared once paginated; the dialog may stay open), 10-min lifetime cap. The bootstrap's `@media print` block strips the preview chrome.
7. **Server-rendered PDF / PNG (Phase 5)** — `GET /api/docs/:docId/pdf` mints a single-use render token, calls the renderer sidecar (Playwright in a separate container), which navigates to `app/pages/_internal/render/[docId].vue?t=<token>`. That page SSRs via `server/api/_internal/render-bootstrap.get.ts`: replays Y.js to materialise the markdown body AND reads theme + title/description/audience/language from the replayed `ymeta` first, the `documents` row only as fallback (`server/utils/documents/docProperties.ts#resolveDocProperties` — only the owner's editor persists properties to the row, so an anonymous doc's theme exists in Y.js alone; reading the row rendered its PDF in the default theme), runs the same pipeline above, returns headless-rendered PDF/PNG bytes. The page never connects to Hocuspocus — Y.Doc state is server-rendered. Failure mode: the API endpoint is the source of truth; if the renderer is down the request 503s and the UI surfaces the error (no fallback to client-side paged.js — they're not byte-identical and silently swapping is worse than a clear failure).

**Why the server path even with a perfectly good client path:** AI tools (`view_pages`, page-screenshot consumers) need a deterministic byte-stable render the model can ingest. A user's local fonts / display zoom / browser would otherwise produce different paged-media output per user. The renderer sidecar gives one canonical render per `(doc, theme, viewport)`.

**Why iframe:** paged.js mutates global head styles + `:root` vars and re-paginates on every call. Running on the host page caused unrecoverable layout contamination. Use CSS `zoom` (not `transform: scale`) for responsive shrinking — zoom shrinks layout box; scale doesn't.

**paged.js quirks:** Polisher only processes `@page` rules from `stylesheets` argument — pass `[{ 'theme.css': cssText }]`. Margin boxes are siblings of `.paged-doc`, not descendants; CSS custom properties don't propagate up. Bake `{title}`/`{date}` into the CSS string directly.

**Preview isolation (security batch B5).** The preview + print iframes have NO `allow-same-origin`: they run in an opaque origin, so a script injection in rendered content can't touch the app's cookies, storage, DOM or same-origin APIs. Consequences, all handled in `app/utils/preview/previewFrame.ts`:
- **postMessage only, typed + checked both ways.** Parent → iframe: `render`, `color-mode` (the iframe can't read the parent's `dark` class; `usePagedPreview` forwards it from a MutationObserver, initial value baked into the srcdoc), `zoom`. Iframe → parent: `iframe-ready`, `paginated`, `iframe-error`, `print-shortcut`, `print-done`, `zoom-state`, `zoom-request`, `zoom-gesture` (see "Preview zoom" below). Parent accepts only `e.source === iframe.contentWindow && e.origin === 'null'` + per-type shape (`parseFrameMessage`); the iframe accepts only `e.source === window.parent && e.origin === <parent origin>` (substituted into the srcdoc) and posts to that origin only.
- **Images.** The iframe's requests are cross-site → no session cookie. Exact own-upload URLs (`/api/files/<thisDoc>/<fileId>`, `ownUploadFileId`) get `?token=<file-access JWT>` — `<img src>` in the HTML (`attachOwnUploadTokens`), header/footer images (`themeToCss` `imageUrl`), custom-CSS url()s (sanitizer `fileUrl`); never links or other URLs that merely contain the path (same rule as the render page's `renderFileTokens.ts`). The token is minted by `GET /api/docs/:docId/file-token` (same `decideFileAccess` gate as `/api/files`; password visitors send their doc JWT as Bearer — `useDocument().getDocJwt`), 15 min, cached + refreshed by `createFileTokenSource`. `/api/files` and the document's brand-kit route `/api/docs/<doc>/brand/<file>` (WP10) are the only endpoints that accept the `file-access` scope. **Brand kit (WP10):** a theme image `/api/brand/<file>` (workspace logo) is mapped by `withOwnUploadToken` / `withRenderFileToken` to `/api/docs/<thisDoc>/brand/<file>?token=` (render page: only for the bootstrap's `brandFiles`), and every workspace font (`brandFonts` from `/token` / the bootstrap) is declared after the theme's font imports via `shared/utils/theme/brandFonts.ts#brandFontFaceCss` (same token). The locked workspace design is applied before rendering (`EditorLayout` `renderTheme`, render bootstrap — `shared/utils/theme/brandLock.ts`). `/api/files` responses carry `Cross-Origin-Resource-Policy: cross-origin` (everything else `same-site`, `server/plugins/csp.ts`) — CORP same-site would block the opaque-origin `<img>`.
- **CSP.** The srcdoc inherits the page's CSP: its inline scripts carry the page nonce (`currentCspNonce()` reads `script.nonce`), no inline `on*=` handlers. `'self'` in the inherited policy still means the app origin — which is how the `/vendor/` scripts, styles and fonts pass.
- **Cost:** keystroke → repaint within noise of the same-origin version (welcome ×10, 31 pages: p50 ~1.25 s vs ~1.30 s; 48-page doc with images/Mermaid/math: p50 ~7.4 s both, incl. the 250 ms debounce), browser memory +1–3 %. Reproduce with `scripts/measure-preview-perf.ts` against the flow test stack.

**Preview zoom + "All pages" overview.** Fit width (default; never enlarged past 100 %), fixed steps 50–200 % (`PREVIEW_ZOOM_STEPS`), free factor 30–300 % from pinch / Ctrl+wheel, and `overview` (pages wrap side by side, thumbnails ≥ 140 px — ≥ 96 px on phones — at most half size). Three layers: `app/utils/preview/previewZoom.ts` (pure: setting type, zoom in/out walk — below 50 % comes the overview, from the overview zoom-in = fit —, shortcut matcher, localStorage key `markoto:preview-zoom` in try/catch, per browser, never per document), `app/composables/preview/usePreviewZoom.ts` (shared `useState` — the pane pill `components/preview/ZoomControl.vue`, the mobile view-mode bar's compact button and View › Zoom all drive it; `command.seq` tells `usePagedPreview` to post a `zoom` message; `usePreviewZoomMenu` builds the dropdown items), and `app/utils/preview/previewZoomFrame.ts` — the engine INSIDE the iframe, self-contained and inlined via `__PREVIEW_ZOOM_SCRIPT__` like the pagination handlers (`tests/dom/previewZoomFrame.test.ts` evaluates the string). The engine only sets `--page-zoom` (CSS `zoom`) + `--overview-gap` on `.pagedjs_pages` and `zoom-scale` / `zoom-overview` classes on `<html>`; it never re-paginates (`reapply(true)` runs after each render's swap, remeasuring the natural page width at zoom 1). Reading position: the page under the viewport centre (or the gesture point) keeps the same spot after a change; an overview click (`zoom-request` `page`) opens that page at fit width, top of the view. The pull-back / push-in is one Web Animations transform on `#mount` (rect of the anchor page before → after, 520 ms; 200 ms between steps; none under `prefers-reduced-motion`), `html.zoom-animating` hides overflow meanwhile. Gestures are applied live in the frame (rAF-batched) and reported once (`zoom-gesture`); the parent stores them without echoing, or switches to the overview when pinched past the minimum. `html { touch-action: pan-x pan-y }` + `gesturestart` preventDefault keep pinch inside the preview. Shortcuts: inside the frame (focus there) the engine forwards Ctrl/Cmd `=`/`-`/`0` as `zoom-request`; with focus elsewhere but the pointer over the pane, `PreviewPane` handles them (the editor binds none). The print block resets zoom, layout and transform (`zoom: 1 !important`, `display: block`, `#mount { transform: none }`); `printPdf` never sends `zoom`, the server renderer / `view_pages` don't use this bootstrap.

**Third-party browser assets are served from our own origin, SRI-locked.** paged.js, KaTeX (stylesheet + woff2 fonts), the highlight.js themes, Mermaid and the web fonts load from `/vendor/` — never from jsDelivr / Google Fonts — so visitors' browsers and the renderer request nothing from a third party and an air-gapped self-host still renders. `modules/vendor-assets.ts` copies them out of the pinned npm packages at every `nuxt dev` / `build` / `prepare` (generator + checks: `scripts/lib/vendorAssets.ts`; output `node_modules/.cache/markoto-vendor-assets`, registered as a Nitro public-asset dir). Paths are versioned (`/vendor/<pkg>@<version>/…`), served `immutable`; the per-family font stylesheets `/vendor/fonts/<slug>.css` are the one unversioned name (`no-cache`, `server/utils/rendering/vendorAssetHeaders.ts`). Version + URL + SRI live in `shared/utils/{pagedjsAssets,katexAssets,hljsAssets,mermaidAssets}.ts` (`*_URL` + `*_SRI`; hljs: `hljsTheme(theme) → {url, sri}` per theme); the bytes are the npm package's, so the hash is unchanged from the jsDelivr days. **Bump:** change package.json + the `*_VERSION` constant, recompute with `openssl dgst -sha384 -binary node_modules/<pkg>/<file> | openssl base64 -A` — the build refuses to start while version or hash disagree (`tests/unit/rendering/vendorAssets.test.ts` pins the same). Mermaid is the single-file IIFE build (`mermaid.min.js`, devDependency, injected as `<script integrity crossorigin>`) — the ESM build's `import()` + ~100 lazy chunks can't be SRI-checked. Parent-context mermaid (server render page only) lives in `app/utils/markdown/mermaidLoader.ts`. The opaque-origin iframe sees our origin as cross-origin: `/vendor/*` answers with CORP `cross-origin` + `Access-Control-Allow-Origin: *`, and every SRI tag keeps `crossorigin="anonymous"` (SRI only fires in CORS mode; fonts are CORS requests anyway). Workbox: `/vendor/**` is NOT precached (~25 MB); the SW runtime-caches it (CacheFirst; font stylesheets StaleWhileRevalidate) for app-shell requests — the sandboxed iframes aren't SW clients and use the HTTP cache.

**Web fonts** (`shared/utils/theme/themeFonts.ts`): 23 self-hosted families from exact-pinned static `@fontsource/*` packages — the 20 picker fonts + JetBrains Mono, IBM Plex Mono, Fraunces (app shell + presets) — plus 4 bundled families (see "Bundled fonts" below). **Documents use static cuts only** (weights 400–900 the package ships, `DOCUMENT_FONT_WEIGHTS`): Chromium/Skia embeds any font with an `fvar` table (and CFF outlines) as Type 3 glyph procedures, so variable fonts made Type 3 PDFs. The app shell keeps the variable cuts of Inter / JetBrains Mono / Fraunces (`@fontsource-variable/*`, the `ui` source; `/vendor/fonts/<slug>.variable.css`, linked by `app.vue` via `uiFontStylesheetUrls`) under their OWN family names `'Inter Variable'` … (`uiFontFamilyName`; `main.css` `--font-*` list them first) — under the theme's name they joined the static faces on the server render page (an app page) and won the matching, so the PDF was Type 3 again. Pinned by `tests/unit/rendering/vendorAssets.test.ts` + the real-renderer test "embeds no Type 3 font in any built-in preset" (`tests/integration/endpoints/docPdf.test.ts`). woff2 only, normal + italic, every unicode-range subset the package ships (a browser downloads only the subsets/styles a page uses), `font-display: swap`, renamed to the theme's family name (`'Inter'`, not `'Inter Variable'`), licence next to the files. `themeFontsImport(theme)` emits one `@import url('/vendor/fonts/<slug>.css')` per family the theme uses; a family outside the registry renders in the fallback stack. The app shell links Inter / JetBrains Mono / Fraunces the same way (`app.vue`); the theme panels link the picker fonts' stylesheets (only @font-face rules — files download when an item shows text in them). `@nuxt/fonts` is disabled (`ui.fonts: false` in `nuxt.config.ts`). Adding a family: install the Fontsource package exact, add a `font(...)` line.

**Theme system (`shared/types/theme.ts:DocTheme`):** Per-doc JSONB in `documents.theme`, mirrored to `ymeta.theme`. Validated by `shared/utils/theme/themeValidation.ts`. Editor panel: `ThemeEditorPanel.vue` (16 accordion sections). Presets in `shared/utils/theme/themePresets.ts` (markoto, Modern, arXiv preprint, IEEE conference paper, Thesis, Technical documentation, Design doc / RFC, Corporate report, Newsletter, Resume; "Tech Report", "Business Report", "Academic Paper" and "Novel" were retired 2026-11 — documents keep the theme they were given, since a preset is copied into the document). Building a new one: `docs/TEMPLATE-WORKFLOW.md`. Font picker from `shared/utils/theme/themeFonts.ts` (23 self-hosted text fonts + the code fonts, see above). Header/footer tokens: `{title}`, `{section}`, `{author}` (cover authors, comma-separated), `{date}`, `{page}`, `{pages}` — inserted at cursor via `data-slot`/`data-position`. User-saved themes shipped (CRUD via `/api/user/themes`). Page sizes A4 / A5 / Letter / Legal (`pageDimensions.ts`).

**Optional theme fields (added 2026-11, theme foundation PR + template variables + engine-structure batches).** `headings.numbering`, `headings.levels` (incl. `align`), `headings.{numberingDepth,chapterLabel,chapterWord}`, `code.{font,background,frame,wrap,lineNumbers}`, `cover.{affiliations,rules,smallCaps,titleWeight,dateFormat,repeatTitle}`, `header.rule` / `footer.rule`, `header.{sectionNumber,sectionMode}` (header only — they apply to `{section}` wherever it is used), `page.margin{Top,Right,Bottom,Left}`, `page.mirrorMargins`, `tables.{captionPosition,captionLabel}`, `blocks.{figureLabel,referenceStyle,captionNumbering,captionLabelStyle}` are `.optional()` in the schema, so themes stored before them stay valid (no migration). Every reader resolves them through `shared/utils/theme/themeOptions.ts` (`resolveCodeOptions`, `headingNumbering`, `numberingDepth`, `resolveChapterLabel`, `resolveSectionToken`, `resolveTitleBlock`, `resolveHeadingLevel`, `runningRule`, `coverTitleWeight`, `coverDateFormat`, `repeatTitle`, `resolvePageMargins`, `mirrorMargins`, `resolveCaptions`, `referenceStyle`, `withThemeDefaults`); presets + `defaultTheme` spell them out (pinned by `tests/unit/theme/themeFoundation.test.ts`) — except the inheriting ones: `cover.titleWeight` (absent = "follow `headings.weight`") and the per-side margins (absent = `page.margin`), set only where they differ. The panel binds them via computed get/set with defaults, so OPENING the panel never rewrites a stored theme. New optional fields: same pattern.

**Heading scale rule.** `headings.scale` is the ratio between neighbouring levels from h4 up: h4 = body, h3 = body·s, h2 = body·s², h1 = body·s³ (`HEADING_SCALE_EXPONENTS`, `headingSizePt`); h5 = body, h6 = 0.9·body. Presets keep h1 within 1.6–2.2× body (test). Space around headings is in body lines (`HEADING_SPACE_ABOVE/BELOW`, above × `spacingScale`), more above than below; stacked headings get half a line; the first block of every page loses its top margin (`data-markoto-page-top`, set by the pagination handler). Display sizes belong to the cover / title block (`cover.titleSize`, weight `cover.titleWeight`). Until 2026-11 h1 was body·s⁵ (33–46 pt). **Per level** (`headings.levels.h1…h4`: `size` × body, `weight` 100–900, `style` italic, `smallCaps`) overrides the scale/weight for that level only — format templates (arXiv 12/10/10 pt). Spacing stays line-based. The cover title (an h1) pins `font-style` / `font-variant-caps` so a per-level h1 look never reaches it. The 1.6–2.2× test checks the scale (`headingScaleSizePt`), not overrides.

**Heading numbers** (`headings.numbering`: `decimal` 1.1, `decimal-dot` 1.1., `ieee` I. / A. / 1) / a) — own level only, `decimal-zero` 01 / 01.1 — `numberLabel`; `headings.numberingDepth` 1–4 = how many levels SHOW a number, every level still counts; `headings.chapterLabel` = "Chapter 3" (`documentTexts().captionLabels.chapter`, per language incl. 第3章, or `headings.chapterWord`) as a block `::before` on the numbered section headings, replacing the number there — `chapterLabelBlock`): CSS counters `mk-h1…mk-h4` on h1–h4 + `mk-toc1…4` on the TOC's nested `li`s (number in `li::before`, entry `a` is flex 1, nested `ul` wraps) — paged.js turns counter-increment/reset into per-element values, so numbers continue across pages. Skipped (no number, counters don't advance): `.markoto-cover-title`, `.markoto-abstract-heading` / `.markoto-abstract-entry` (set by `markAbstract`), and Pandoc's `.unnumbered` (`# References {.unnumbered}`; `{-}` is turned into the class by `markdownUnnumbered.ts`, right after the attrs rule) with its TOC entry marked `.markoto-unnumbered-entry` by `markUnnumbered` (composeFinalHtml, numbering on). **Numbers count from the highest numbered level used:** `markHeadingStructure` (`headingStructure.ts`) puts `markoto-num-from-hN` on the numbered headings when that level is h2–h4, and `numberingBlock` emits per-base `::before` labels for those (one extra class, wins on specificity; counters/resets unchanged). The TOC is already relative (toc-done-right nests from the highest level used). Per-level `align: 'center'` → `text-align: center` on that level.

**Code blocks.** `renderMarkdown` wraps every code line in `<span class="code-line" data-line="N">` (`wrapCodeLines`, re-opens hljs spans across line breaks; mermaid fences stay plain) and turns ```` ```ts title="x.ts" ```` into `<div class="code-block"><div class="code-title">x.ts</div><pre>…` (escaped text, fence renderer override, `fenceTitle`). `themeToCss` paints the box on `<pre>` (hljs `.hljs` padding/background/overflow neutralised; base colours in `hljsAssets.ts#HLJS_THEME_COLORS`, checked against the stylesheets): dark hljs themes keep their background, light ones get a tint unless `code.background` says otherwise; `frame` rule/box; `wrap` (default on — `overflow-x: auto` clipped long lines in print); `lineNumbers` via `attr(data-line)` (no counters: paged.js would emit one CSS rule per line). Blocks ≤ 15 lines (`CODE_KEEP_TOGETHER_LINES`) are `break-inside: avoid`; longer ones split; `.code-title` keeps with its block (handler).

**Title block** (`cover.layout: 'title-block'`, papers): no cover page — `coverHtml.ts#buildTitleBlockHtml` emits title, subtitle, author cards (+ `cover.affiliations[i]`, `white-space: pre-line`), date and the abstract into a flowing `<section class="markoto-cover markoto-title-block">`; `@page :first` drops the running header. **Abstract convention:** the document's leading section headed "Abstract" (any level; also Zusammenfassung / Résumé / Resumen / 概要 / 摘要 …, `titleBlock.ts#ABSTRACT_HEADINGS`) — plain portable Markdown, no theme/ymeta prose field. `composeFinalHtml` moves it in (`extractAbstract`: heading → `.markoto-abstract-title`, its TOC `li` removed); other layouts with numbering only mark it (`markAbstract`). A leading `# <title>` whose text equals the document title (normalised) is dropped in title-block layouts (`titleBlock.ts#dropTitleHeading`, before `extractAbstract` — as the first heading it also hid the abstract); a different first h1 stays. `cover.rules` = heavy rules around the title (arXiv), `cover.smallCaps` = small-caps title/subtitle (all layouts).

**Document structure markers** (`composeFinalHtml` → `headingStructure.ts`, `references.ts`, `tableCaptions.ts`; parsed DOM, sanitised again after): `markoto-section-heading` on every heading of the highest level used (h1, else h2 …) + `markoto-first-section` on the first one (paged.js clones `.paged-doc` per page, so `h1:first-of-type` matches per page — `columnSpanBlock` uses the class now; it and the TOC spanner are emitted only with `layout.columns > 1`: in a single-column doc a spanner stopped collapsing its margins with its neighbours); `{section}` = `string-set: mk-section content(text)` on `.markoto-section-heading` (emitted only when a slot uses the token; paged.js `string()` → first on the page, else the previous page's last). paged.js 0.4.3 `string-set` supports only `content()` and `attr()`, and `content(text)` can't see the CSS number: with `header.sectionNumber` `markHeadingStructure` writes `data-markoto-section="3 Procedures"` (number formatted like the CSS, `sectionNumberLabel`; unnumbered = title) and the rule reads `attr(data-markoto-section)`. `header.sectionMode: 'start'` → `string(mk-section, start)`: the heading only when it opens the page (paged.js compares its top with the page content's — works because `.paged-doc > :first-child` has no top margin), else the section running on. The section headed References / Bibliography / Literatur / Références / Referencias / 参考文献 … (`REFERENCE_HEADINGS`, top-level children, until the next heading of the same or a higher level) → its `ol`/`ul`/`p` get `markoto-references` (survives page/column continuation; heading `markoto-references-heading`); `blocks.referenceStyle` `hanging` (`--doc-reference-indent`, default 1.5em) / `brackets` (`[n]` markers via `::marker`). **Table captions:** `markdownTables.ts` turns a paragraph starting `Table:` / `table:` / `:` right after (preferred) or before a table — or a trailing GFM row whose first cell is that and the rest empty — into `<caption>` (first child; attrs `{#id}` land on it); `tables.captionPosition: 'below'` → `moveCaptionsBelow` appends it after the rows (HTML parsers keep it there) so a split table shows it under its LAST part, `caption-side: bottom`. `tables.captionLabel` / `blocks.figureLabel` → `::before` "Table N: " / "Figure N: " with counters `mk-table` / `mk-figure` (only captioned tables / non-empty figcaptions count), words from `documentTexts().captionLabels` (runtime `captionLabels`, document language). `blocks.captionNumbering: 'chapter'` → "Figure 3.1": `captionNumbers.ts#numberCaptionsByChapter` writes `data-markoto-number` on every table caption / non-empty figcaption (chapter = numbered section headings so far; before the first chapter or under an unnumbered section a plain number) and the label prints `attr(data-markoto-number)` (counters can't reset on "whatever level the sections are"). `blocks.captionLabelStyle: 'stacked'` → bold upright label on its own line, no separator (APA), in the text colour (`--doc-text`: the bold cut in the default caption grey, small and often mono, read as a light weight — JetBrains Mono 700 is loaded and used). **Cells:** `markdownTables.ts` also wraps number+unit/% (`+8.1 %`, `180 ms`), currency+amount, comparison+number, short codes (`SEV-1`), dates (`30 Jan 2027`, `12. Januar`, `Jan 12, 2027`, `2027-01-30`; en/de/fr/es month names) and short hyphenated words (`on-call`, ≤ 16 chars) in table cells in `span.markoto-nowrap` (`white-space: nowrap`) — fixed short patterns only, so wide tables still fit. **Template-CSS variables:** `--doc-{body,heading,meta,mono}-font` (full stacks) + `--doc-accent` on `.paged-doc` and `.pagedjs_page` (margin boxes), with `--doc-brand/secondary/text`. **Per-side margins:** `resolvePageMargins` everywhere a margin is used (`@page`, running-rule gap per edge, mermaid text height/width). Cover / title-block title: `text-wrap: balance`, and `coverHtml.ts#keepNumbersTogether` turns the space between two words that both contain a digit into a no-break space (balance alone broke "Q3 / 2026 Quarterly Report"); `keepCompoundsTogether` wraps hyphenated compounds in `span.markoto-nobreak` (`white-space: nowrap`; not U+2011 — many fonts lack the glyph and copied text would lose the hyphen), so "field-/service" can't happen. Page covers show `cover.affiliations[i]` under each author too (`.markoto-cover-affiliation`, CSS only when one is set). `cover.repeatTitle` appends `div.markoto-repeat-title` after the cover / title block (no heading: no number, TOC entry or `{section}`). `cover.dateFormat` (`locale` / `us` / `iso`) goes through `documentTexts` (cover + `{date}`). `page.mirrorMargins` → `@page :left` with the side margins swapped (paged.js left pages).

**Marker classes for template CSS** (so presets don't need `:has()` / sibling selectors, which paged.js rewrites): `markdownMarkers.ts` (markdown-it core rule + fence renderer) — `p.markoto-labelled` (opens with a bold run-in label ending in `.`/`:`/`!`/`?`, text after it), `.markdown-alert.markoto-alert-labelled` (its first paragraph is labelled), `.markoto-endpoint` on a paragraph or `http` fence holding exactly `METHOD /path` with `span.markoto-http-method` + `span.markoto-http-path`; `documentMarkers.ts` (composeFinalHtml, after `markHeadingStructure`) — `p.markoto-lead` (the body's first top-level block when it is a paragraph, past a TOC / page break / rule = the paragraph under the cover or title block), `span.markoto-opening` around the first words (≤ 4, ending after clause punctuation; never inside KaTeX/footnote spans) of the lead and of the first paragraph after every top-level section heading, the way `dropcapWrap.ts` wraps the cap (it continues after a cap). `body.dropCap: 'every-chapter'` caps those chapter-opening paragraphs (`capParagraph`, same rules); `true` stays the single cap on the body's first paragraph.

**Running-head rule** (`header.rule` / `footer.rule`): a 0.4 pt line in the text colour across the full text width, painted as a background on paged.js's margin ROW (`.pagedjs_margin-top` / `-bottom`, exactly the text width) — not a border on a slot box (only under that slot) nor at the row's edge (a whole margin away). The rule sits `runningRuleGapPt` = 0.35 × margin from the text block (25 pt at 1in = LaTeX `headsep`); with it the slot boxes get `vertical-align: bottom` (+ padding past the rule) so the text sits 2 pt above the line. Emitted only when the edge has running text; with a cover page / title block, `:not(.pagedjs_first_page)` (paged.js marks every page's boxes `hasContent` from the generic `@page` rule, so `:has(.hasContent)` can't detect page 1).

**Bundled fonts** (not on Fontsource): TeX Gyre Termes / Heros, Latin Modern Roman / Mono (GUST Font License), WOFF2 subsets committed in `fonts/<slug>/` with LICENSE + MANIFEST (built by `scripts/build-bundled-fonts.py` from CTAN; Latin + Latin Extended + punctuation/currency/arrows/math operators, layout features incl. `smcp`). **Greek:** TeX Gyre keeps its monotonic Greek (U+0370–03FF in its range); Latin Modern has capitals only, so both LM families get Greek companion faces cut from CM Unicode (OFL, `cmu-greek-*.woff2`, `LICENSE-CMU.txt` + `MANIFEST-CM-Unicode.txt`, renamed "markoto Greek Serif/Mono" — RFN; vertical metrics copied from LM) served under the LM family name with `unicode-range: U+0370-03FF, U+1F00-1FFF` (per-face `unicodeRange` + `licence` in `BundledFace`). "3 μm" no longer falls back to a CJK system font in the PDF. A changed subset needs a new URL: bump the version suffix (`2.004-2`), the files are served `immutable`. `themeFonts.ts` `bundled(...)` source; `scripts/lib/vendorAssets.ts` copies them to `/vendor/fonts/<slug>@<version>/` + stylesheet like the Fontsource families (so CSP `font-src 'self'`, the opaque-origin CORS/CORP headers and the renderer's APP_URL allowlist already cover them; file hashes are part of the vendor inputs key). Add one: files + licence in `fonts/<slug>/`, one `font(..., bundled(...))` line. `code.font` choices: `CODE_FONT_NAMES` (mono families, not in the text pickers).

**paged.js selector gotcha:** paged.js splits every selector list at commas — a comma inside `:is()`/`:not()`/`:has()` throws in its `querySelectorAll` and the whole render fails. Spell lists out (`tests/unit/theme/themeFoundation.test.ts` checks all generated CSS).

**Custom CSS (`theme.customCss`, optional, ≤ 64 KB):** documents only — appended LAST by `themeToCss` via `runtime.customCss` (the sanitizer's `CustomCssResult`, never the raw string; `themeToCss` never reads `theme.customCss`). One sanitizer, `shared/utils/theme/customCss.ts` (css-tree parser/walker/generator subpaths, exact-pinned; types for the subpaths in `shared/types/css-tree-subpaths.d.ts`), used at WRITE time (`meta.put`, saved themes, workspace default, AI/MCP `update_theme` → 400 `theme/custom-css-invalid` + `data.issues[{code,message,line,column}]`) AND at RENDER time in all three consumers (`usePagedPreview`, `printPdf`, `_internal/render/[docId].vue`) — mandatory, `ymeta.theme` is writable over Y.js. Browser code loads it lazily through `app/utils/preview/customCssLoader.ts` (~23 KB gzip; docs without custom CSS never fetch it). Checks run on the AST with decoded identifiers: at-rule allowlist (`@media/@supports/@page`+margin boxes/`@keyframes/@container/@layer/@font-feature-values`; `@charset` dropped silently), no `expression()`/`behavior`/`-moz-binding`/`javascript:`/`vbscript:`, no `var()`/`env()`/`attr()` inside image functions (`image-set`/`image`/`cross-fade`/`src`/`element` — the substituted value would skip the URL check), nesting > 32 levels or a parser exception fails closed (empty CSS + `syntax` issue; `sanitizeCustomCssForRender` also catches and renders without custom CSS), `url()` + url-taking functions (`image-set`, `image`, `cross-fade`, `src`) only to `/api/files/<thisDocId>/<fileId>` (relative or allowed app origin → normalised) or base64 raster `data:image/*` (no SVG), custom-property values parsed too, unparseable `Raw` chunks dropped unless inert. Output = css-tree re-serialisation with every `<` escaped as `\3c ` (no `</style`, `<!--`, `<script`). The render page maps own-upload URLs through `fileUrl` (adds the file-access `?token=` for confirmed uploads) and preloads `result.urls`. Applying a saved theme / creating a doc from one / AI base themes drop rules pointing at another doc (`adaptCustomCssToDoc`); built-in presets keep the doc's CSS (`themeFromPreset`: a preset's template CSS — arXiv — goes in front of the author's, and an unchanged copy of a previous preset's template is replaced, not stacked; preset CSS is checked by `tests/unit/theme/themePresetCss.test.ts`); duplicates rewrite the doc id (`withThemeDocId`). UI: `components/document/ThemeCustomCssSection.vue` (CM6 + `@codemirror/lang-css`, mounts on intersection, emits only valid CSS). The sync-server keeps a SHA-256 of `ymeta.theme` (not the JSON) as its `theme.changed` baseline in Valkey.

## Documents at scale (charts, pagination, tables, cover)

What makes a 15-page report paginate and look like one document. Same code in all three render paths; the render harness pattern (`renderMarkdown → transformMermaid → composeFinalHtml → themeToCss → paged.js`, then Playwright `page.pdf`) reproduces the server PDF outside the app.

- **Document language drives in-document text** (`shared/utils/documents/documentLocale.ts`, `documentTexts(theme, language)`): the cover date + `{date}` token (`theme.cover.date` `YYYY-MM-DD`, empty/absent = today, written out per language: `29 October 2026` / `29. Oktober 2026`; plain `en` uses day-month-year), the TOC title (sentence case: Contents / Inhalt / Sommaire …) and chart number formats. Follows `ymeta.language` (free text tolerated, unknown → `en`), never the viewer's UI locale. Consumers: `usePagedPreview` (+ `PreviewPane` `language` prop), `printPdf` (`language`), the render page (bootstrap `language`). `composeFinalHtml` takes the formatted `date`. `cover.date` is optional in the schema (old themes stay valid); `themeValidation` and the ymeta contract share the schema; AI `update_theme` accepts `cover.date`.
- **Mermaid config** (`shared/utils/markdown/mermaidConfig.ts`, `buildMermaidConfig(theme)`): font = body font always; label size = body size, floor 11px (≈8pt); xy-charts AND gantt charts (`ganttLayout`: `useWidth`, section/task labels at body size, taller bars, right padding for a short closing label) drawn exactly one text column wide (`textColumnWidthPx`) so their text isn't scaled; sequence diagrams (`sequenceLayout`) with `wrap: true` and box + gap sized so 4 participants fill the column (messages wrap between lifelines; one long message used to make the diagram 3 columns wide and the text ~6pt); `themeCSS` (`mermaidThemeCss`): gantt axis labels sized (Mermaid hard-codes `font-size="10"`), beside-the-bar labels in the document font with a paper-coloured halo, the "today" line hidden (a print shouldn't depend on the render date); flowcharts with tighter spacing; pie text larger (pies are shown smaller, see below); root `htmlLabels: false` (plain SVG `<text>`, no `<foreignObject>`); `securityLevel: 'antiscript'` (the iframe re-forces it). `mermaid.theme === 'document'` (the new default, enum value added) = Mermaid `base` + themeVariables from brand/heading/text/secondary/paper and an accent-led categorical palette (`shared/utils/theme/themeColors.ts`, OKLCH, every entry dark enough for white slice labels; the first six sit on six GREYSCALE levels — `greyLightness` = cbrt(luminance) — ordered so neighbouring entries, and a pie's last + first slice, differ for any series count: ≥ 0.1 for ≤ 3 series, ≥ 0.05 up to 6; entries 7–12 repeat the levels in other hues; the accent stays exact, the heading ink too when it is ≥ 0.12 lighter/darker); xy-chart bars get a lighter accent so a line in heading ink reads over them. Built-in themes keep Mermaid's colours (explicit choice wins).
- **Charts in the page's font: `<img>` for layout, inline SVG after.** An SVG loaded as an image can't use web fonts, and an inline SVG gets split by paged.js. So diagrams paginate as `<div class="mermaid mermaid-<kind>"><img data:svg width height>` and are swapped for the SVG after `preview()` resolves (`inlineMermaidSvgs` in `mermaidLoader.ts` — DOMPurify SVG profile, since the render page runs in the app origin; the iframe copy only drops `<script>` because it is the opaque-origin sandbox). Same intrinsic size + one CSS rule for `img` and `svg` → nothing reflows. A diagram still containing `<foreignObject>` stays an image. Before rendering, the body font is loaded (`document.fonts.load`, bounded) so Mermaid measures labels in it; the render page now injects the font import BEFORE `transformMermaid`. `finishMermaidSvg` sets pixel width/height from the viewBox and formats pie legend values (`[3320]` → `3,320`) and xy-chart axis ticks for the document locale; `thinAxisTicks` thins a crowded numeric axis to ≤ 8 labels on a nice step (Mermaid asks d3 for ~10 ticks and has no tick-count option, e.g. 15 labels for 0–7000). User CSS that targets `.mermaid img` only applies during layout — target `.mermaid > svg` too.
- **Diagram sizing** (themeToCss `mermaidBlock`): natural size, `max-width: 100%`, `max-height` 45% of the text area; pies (`.mermaid-pie`) ≤ 85mm.
- **Pagination handlers** (`app/utils/preview/pagedHandlers.ts`, a paged.js `Handler` registered once per window): `onOverflow` moves the break so that (1) headings (and `dt`, `.code-title`, `p.table-caption`, a ≤ 2-line lead-in ending in `:`) stay with the next block (keep-with-next; paged.js 0.4.3 ignores `break-after: avoid-page`), also when fewer than 3 lines of their section would stay on the page (`headingNearBreak`), (2) anything with computed `break-inside: avoid` moves whole — EXCEPT short code blocks / tables (the ≤ 15-line / ≤ 12-row keeps) when moving them would leave ≥ 5 body lines and ≥ 10 % of the text height empty (counting the heading / lead-in that goes along): `splitKeptBlock` sets inline `break-inside: auto` (+ `data-markoto-split`), re-runs paged.js's `findOverflow` (the Layout instance is onOverflow's 4th argument) and keeps the split only with at least a third — and ≥ 3 code lines / table rows — on each side (else undo, move whole), (3) tables break between rows only, with at least 3 body rows on each side of a split — more rows are carried over, or the table moves whole (`rowsFrom` reads `chunker.source`; the page may hold only part of the table while it is laid out, so totals = rows before + rows still to come), — and a closing block of bold rows (Subtotal · VAT · Total: first cell all bold, single plain rows between allowed, ≤ 4 rows and ≤ half the table — `totalRows`) goes over only with ≥ 3 rows before it; a break paged.js puts at the `<tbody>` counts as its first row (no lone header row), (3b) code blocks split between lines with ≥ 3 lines on each side (`codeBreak`, line numbers from `data-line`, total from the source), (3c) lists: never carry one item over nor leave one item alone at the foot, a list of ≤ 4 items moves whole, a list right under a heading / lead-in keeps ≥ 3 items with it or the heading goes along (list moves only when that leaves ≤ 40 % of the page empty, `nearPageEnd`; items kept whole by template CSS count too), (4) a paragraph / list item / `dd` never leaves one line behind, nor carries one line over (widow: break one line earlier, else move the block) — so a page can end a line short when the next paragraph has only two lines, (5) a diagram (`.mermaid`) that doesn't fit the rest of the page is scaled down to as little as 75 % (CSS `zoom` on its box — survives the img → SVG swap; `data-markoto-fit`) before it moves — the first scale is estimated from the free space, then tried in 0.03 steps down to 75 % (the estimate came out a few % too large, so a diagram that fit at 92 % moved and left a third of the page empty). `afterPageLayout` marks the first block of each page (`data-markoto-page-top` → no top margin) and hides a plain `<hr>` that opens or closes a page (`data-markoto-page-edge`) — a rule drawn as a glyph (`::before`/`::after` content: `hrStyle: 'asterism'`, the manuscript's `* * *`) stays visible, it marks the break at the page turn. **Hidden nodes:** paged.js finds the overflow by rects, and a `display: none` node's all-zero rect (x = 0) lies right of the off-screen page → it always "overflowed" (page 1 of a two-column newsletter held only the masthead, the next page repeated content); `renderNode` gives every hidden clone a zero-size `getBoundingClientRect` at its flow position (`placeBoxless`). **Rewritten selectors:** paged.js's Following (`+`) and NthOfType (`-of-type`) handlers re-insert their rules as `[data-following*=id]` (specificity 0,1,0 — `h1 + p` lost to `.paged-doc p`); `processSelectors` is replaced on both so the rule is `:where(mark):is(<original>, :where(mark))` (exact matches, original specificity, trailing pseudo-element kept outside). **Multi-column:** a top-level table, diagram or figure wider than its column gets inline `column-span: all` (`data-markoto-wide`; for a diagram `scrollWidth` counts — the box is column-wide, the drawing isn't); so does a table that only fits its column by breaking code or words in its cells apart (`overflow-wrap: anywhere` keeps it column-wide): it is measured once with `data-markoto-measure` (themeToCss switches the breaking off for that attribute) and spans when it is wider unbroken (`data-markoto-measured` once complete). Before a spanning block Chromium BALANCES the columns, and there it honours an inline `break-after: avoid` — so every keep-with-next block (heading, `dt`, code title, lead-in ending in `:`) gets one (without it a heading opening the column set stayed in column 1 and its text went to column 2); the engine keeps `column-fill: auto` (a template opts into `balance`, as the newsletter does — balancing also the IEEE format's last page would differ from the class). Every move requires other content before it on the page (no loops / empty pages). `renderNode` clones the source `<thead>` into a table continued on a new page (`markoto-repeated-thead`, data-refs stripped). **Delivery:** the function is self-contained and the iframe receives its `toString()` as a nonce'd inline script (`PAGED_HANDLERS_SCRIPT`, `__PAGED_HANDLERS_SCRIPT__` placeholder, function replacer) — keep it free of imports/module references; `tests/dom/pagedHandlers.test.ts` evaluates the string.
- **Column breaks (multi-column themes):** the breaks between the columns of one page are Chromium's, and it ignores `break-after: avoid` / `avoid-column` there (nested in paged.js's own column fragmentation). The handler's `layout` hook (runs before every overflow check) gives a keep-with-next block that ends a column — or has < 3 line boxes of its next block left in that column while the block continues in the next one — an INLINE `break-before: column` + `margin-top: 0` (`data-markoto-column-break`; inline because paged.js strips `break-*` declarations from stylesheets and turns them into data attributes), taking a run of stacked headings along and only when something stays above it in the column. Page-end breaks stay with `onOverflow`. Count line boxes (a range's client rects), not the next block's fragment height: a fragment reaches down to the column end.
- **Footnotes in multi-column pages:** paged.js's `Footnotes.moveFootnote` reasons as if the page had one column — a call near a column end makes it clip the note area above the call or defer the note to the next page, which in two columns is often a page holding only the note. `registerPagedHandlers` wraps `moveFootnote` (found in `Paged.registeredHandlers` by its method name; the vendored build keeps method names) and, ONLY when `.paged-doc` has `column-count > 1` and the call is on the page, takes a deferred note back from `needsLayout` / removes the clip and sets `--pagedjs-footnotes-height` to the full height (paged.js's own formula, whole-pixel margins), unless that is more than half the page. If the call then really leaves the page, paged.js's `afterOverflowRemoved` drops the note and it is placed again with its call. Notes still span the page width (per-column note areas would need a different content-area height per column). Known Chromium edge: a title block whose children are ALL `column-span: all` (template CSS `.markoto-cover { column-span: none }` + spanning title/authors, no abstract) leaves an empty trailing fragment that Chromium can put in the overflow column once a footnote resizes the page → "Unable to layout item" + a title-only first page; give such a cover in-flow content or let it span.
- **Break CSS:** headings `break-after: avoid-page; break-inside: avoid`; `img, blockquote` avoid, `pre` / `.code-block` only up to 15 lines; widows/orphans 2; only SHORT tables (≤ 12 body rows, `table:not(:has(tbody tr:nth-child(13)))`) avoid — long tables split with repeated headers.
- **Cover in multi-column themes:** `.paged-doc .markoto-cover { column-span: all; width: 100% }` for every layout, emitted ONLY when `layout.columns > 1` — `column-count` sits on `.paged-doc` (the cover's parent), so without the spanner the cover was laid out in the first column (half-width band, title centred left). Never in single-column themes: there the nearest multicol ancestor is paged.js's own page-content box (it fragments with CSS columns) and a spanning cover made paged.js drop everything after it (one-page PDF; `docPdf.test.ts` catches it). Pinned by `tests/unit/theme/themeToCss.test.ts`; verified with the render harness in Chromium + paged.js (same engine as the renderer).
- **Editorial cover:** short accent rule above the title, hairline above author/date, and a full-bleed accent band along the top edge when there is no logo (`markoto-cover--no-logo`, set by `coverHtml.ts`).
- **Table attributes:** `{.class}` on the line right under a table applies to the table (`markdownTableAttrs.ts` turns the attrs-only trailing row markdown-it parsed back into the paragraph `@mdit/plugin-attrs` expects). The blank-line form works too.
- **Footnote separator:** `transformFootnotesForPagedMedia` also removes markdown-it-footnote's `<hr class="footnotes-sep">` (it printed as a stray rule at the end).
- **Footnotes** use the BODY font at 0.8 × body size (`@footnote` + `.footnote`), under a short rule (a third of the width, a background gradient on `@footnote`); the meta font made them look like code.
- **Heading ids vs DOMPurify:** `SANITIZE_DOM` drops an `id` that names a `document` / `<form>` property (`method`, `title`, `action`, …). That was the "Method → page 0" TOC bug (no id → `target-counter` never resolved). `defaultSlugify` → `clobberSafeId` adds `-section` to such slugs, checked like DOMPurify does (`slug in document || slug in form`); pinned by `tests/dom/renderMarkdownHeadingsCode.test.ts`.
- **Theme shots:** `scripts/render-theme-shots.ts` / `make theme-shots` (needs a running app with `NUXT_ANON_GATE_ENABLED=false`) renders a Markdown file per preset through the real preview and writes per-page PNGs + contact sheets; fixtures in `tests/fixtures/theme-shots/` (`kitchen-sink.md`, `paper.md` + `paper-patch.json` / `latex-patch.json`, `arxiv.md` + `arxiv-patch.json`, `ieee-conference.md` + `ieee-conference-patch.json`). ## Markdown Comments

`<!-- ... -->` comments are stripped from the rendered preview/PDF/share view but stay in the markdown source. Two markdown-it rules in `renderMarkdown.ts:commentPlugin`:

- **Block rule** — a line (or multi-line range) whose only non-whitespace content is a comment is consumed entirely. Closes on the line containing `-->`; trailing real content on the close line aborts the match (lets the inline rule handle it).
- **Inline rule** — `<!-- ... -->` mid-paragraph is stripped in place; surrounding prose flows around the gap.

Pagebreak (`<!-- pagebreak -->`) wins by registration order — the pagebreak rule runs first and short-circuits its exact pattern.

**Toolbar + menu:** `toggleComment` in `editorCommands.ts` wraps the selection in `<!-- ... -->` (toggleWrap-style: empty → drops `<!-- | -->` cursor inside; selection → wraps + re-selects inner; pre-wrapped → unwraps). Surfaced as `i-lucide-message-square-dashed` button in `EditorToolbar.vue` (after page-break + TOC) and as an "Comment (hidden from preview)" item in the `EditorMenuBar.vue` Insert menu.

**AI vocabulary:** `server/utils/agentic/markdownReference.ts` documents the syntax so the AI knows it can leave private notes for the writer. Templates use this heavily — every section in the recipe / business-plan / academic-paper / etc. templates has a `<!-- ... -->` brief telling the AI (or the user) what to write there.

**Audit script** (`scripts/audit-markdown-pipeline.mjs`) covers 11 cases including pagebreak precedence, multi-line blocks, mid-paragraph stripping, unterminated fallback (escapes to literal `&lt;!--`), code-fence preservation. Run before adding any syntax claim to `markdownReference.ts`.

## Gotchas

- **`markdown-it-emoji`** needs `.full`: `const emoji = (mod as any).full || (mod as any).default || mod`.
- **`highlight.js` CSS** must be dynamically imported inside `initMd()` — otherwise code blocks are all white.
- **Footnotes need `transformFootnotesForPagedMedia()`** — markdown-it-footnote puts all footnotes at end of doc; paged.js `float: footnote` needs inline `<span>` at the ref site.
- **Iframe bootstrap lives in `pagedPreviewIframe.html`, not a template literal** — imported as a raw string via `?raw` in `previewFrame.ts`. Placeholders (`__CSP_NONCE__`, `__PARENT_ORIGIN__`, `__INITIAL_DARK__`, vendored-asset URLs + SRIs) substituted by `buildPreviewSrcdoc`; `tests/unit/rendering/pagedPreviewIframe.test.ts` pins the contract (nonce on every inline script, no inline handlers, no `parent.document`, origin-checked messaging).
- **Never give the preview/print iframe `allow-same-origin`** — and never read `iframe.contentDocument` / call into `contentWindow` from the app or from tests (Playwright: `frameLocator('iframe')` / `EditorPage.previewRoot()`). `tests/nuxt/previewFrame.test.ts` + `tests/e2e/flows/preview-isolation.spec.ts` pin it.
- **Mermaid labels** — `htmlLabels: false` (root + flowchart) so diagrams are pure SVG `<text>`: they serialise as XML, survive the SVG sanitiser and inline cleanly. Label boxes are only right when the body font is loaded before `mermaid.render` (both paths do it); `overflow: visible` on the diagram keeps a slightly short label from being clipped.
- **srcdoc links navigate the iframe** — the bootstrap captures every `<a href>` click: `#…` → `preventDefault + target.scrollIntoView()`, anything else → `preventDefault` (the sandboxed preview must never navigate itself).
- **`html: false` doesn't block manually pushed tokens** — custom block rules that call `state.push('html_block')` render verbatim regardless. Use this for controlled HTML emission.
- **TOC: anchor plugin must load BEFORE toc plugin** — `markdown-it-anchor` assigns IDs; `markdown-it-toc-done-right` reads them. Share one `slugify`.
- **KaTeX SVG** — `\underbrace`, `\sqrt`'s radical, `\widehat`, `\cancel`, arrows are inline `<svg><path>`/`<line>`. `sanitizeHtml.ts` allows `svg`/`path`/`line` ONLY as KaTeX emits them (`onElement`: an `<svg>` inside `.katex-html`, `path`/`line` directly in it; `onAttribute`: per-element geometry allowlist, SVG-only attributes dropped on HTML elements) — before, every such symbol vanished.
- **KaTeX inherits paragraph text properties** — a justified paragraph's `text-align-last: left` start-aligned KaTeX's centred single-line rows (`\hat` accents slid off their base, fraction numerators / limits left-aligned, display math flush left). `themeToCss` `katexBlock` resets `text-align-last`, letter/word spacing, `text-transform`, `font-variant`, `font-feature-settings`, `hyphens` on `.katex`.
- **Display math wraps, never clips.** `.katex-display` has no `overflow` (`overflow-x: auto` = cut off on paper) and `.katex-display > .katex { white-space: normal }`: KaTeX already splits a formula into one box per TeX break point (after an outer-level relation / binary operator), so a too-wide display can wrap. The pagination handler makes it wrap the TeX way (`pagedHandlers.ts`, display math): `afterParsed` moves each box's trailing relation / binary operator (with its spacing) to the start of the next box, so the break comes BEFORE the operator (one-line displays are unchanged); in `layout` a wrapped display gets `text-align: left` + a hanging indent at its first relation (2 em without one, or when it sits past the middle; `text-indent` on `.katex-html`, reset to 0 on KaTeX's boxes by `katexBlock`), the runs between relations are grouped no-wrap (`span.markoto-math-run`) so a line breaks at a relation before it breaks at a `+` (a run too long for a line is ungrouped), and the block of lines is centred on its widest line (`data-markoto-math-wrapped`). A piece wider than the column (matrix, big fraction, aligned block) shrinks the whole formula onto one line if ≥ 85 % does it, else just enough for that piece, never below 85 % (`MIN_MATH_SCALE`, font-size on `.katex`, `data-markoto-math-scale`); still too wide, it spans a multi-column page (`data-markoto-wide`, fitted again at page width) or stays on one line running into the margin. Author line breaks (`\\`) are left alone. **Math size follows the body font** (`mathFontScale`): 1 em next to faces with a Computer-Modern-sized x-height (Latin Modern Roman, TeX Gyre Termes, Crimson Text, EB Garamond, Cormorant Garamond — measured), 1.05 em otherwise.
- **Code is literal:** `font-variant-ligatures: none` on `code`, `pre`, `.code-title` (JetBrains Mono drew `|=` as ⊨). **Inline code breaks only between tokens:** `renderMarkdown`'s `code_inline` rule wraps each space-separated token in `span.markoto-code-token` (`wrapCodeTokens`; spaces stay text, copy gives the original) — an inline block with `max-width: 100%` + `overflow-wrap: anywhere`, so `--data-urlencode` never breaks after a hyphen but a token longer than the line still breaks.
- **Headless Chromium must run with `--font-render-hinting=none`** (renderer + `render-theme-shots.ts`): by default it lays text out with hinted whole-pixel advances, and the PDF keeps them — unhinted fonts (TeX Gyre Heros: T 10 px instead of 8.15 px at 10 pt) printed "T his", "Dat e". The font files are fine (HarfBuzz advances correct).
- **KaTeX inline `style`** — DOMPurify must allow `style` attribute; add `math`/`semantics`/`mrow`/etc. to the allowlist. Every `style` value is filtered to `ALLOWED_STYLE_PROPERTIES` in `sanitizeHtml.ts` (no `url()`, `var()`, quotes/escapes, `position` other than relative/static, viewport units). If KaTeX starts emitting a new property, add it there — `renderMarkdownXss.test.ts` compares our output against raw KaTeX.
- **`@mdit/plugin-img-size` in our stack does NOT parse `=WIDTHxHEIGHT`** — despite the package's readme. Use `@mdit/plugin-attrs` syntax: `![alt](url){width=50%}`. The audit script catches mis-documented syntaxes.
- **CSS `zoom` not `transform: scale`** — `scale` leaves layout box full-size and overflows; `zoom` shrinks both.
- **Markdown comments via custom block + inline rules (NOT via `html: true` + DOMPurify-strip).** Flipping `html: false` → `html: true` to let DOMPurify strip `<!--...-->` would reopen XSS surface. Custom rules give us comment stripping without changing the html-escape gate.
